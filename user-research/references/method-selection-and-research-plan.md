# Method Selection and Research Plan

## 1. Decision-first brief

先记录：

- decision、可选动作和 decision deadline；
- 当前证据、关键未知和错误决定的代价；
- target users/context、需要多新鲜的经验；
- 需要的是探索、描述、评价、预测还是因果结论；
- 时间、预算、渠道、语言、隐私和可访问性约束。

把候选 research questions 按决策价值、evidence gap、方法适配、可行性和负担排序。一个活动可回答多个紧密相关问题，但不要为了复用参与者而拼接不同研究主线。

## 1.1 Evidence–cost ladder

每个 research question 在推荐真人同步研究前，比较能支持同一决定的证据阶梯：

1. 已有 telemetry、客服/VOC、取消原因、评论、历史研究和相关桌面调研；
2. 低成本异步证据：事件锚定开放题、异步文字/音视频 follow-up、未主持任务或短 diary；
3. Survey-first 后只对关键分群、矛盾结果和未知尾部做少量定向访谈；
4. 探索访谈先行；
5. 高投入纵向、现场或实验研究。

默认选择满足最低证据要求的最低成本组合，而不是信息最丰富但成本最高的方法。必须同时写明：

- 省略高成本方法会失去什么信息；
- 哪种观察结果会触发升级；
- 可否先做 reversible 的小规模阶段；
- 后续阶段是否真的依赖前一阶段。

访谈不是发现未知需求的唯一入口，但开放问卷和既有 VOC 通常缺少追问、上下文和反例能力。用它们替代访谈时，限制必须进入结论。

## 1.2 Existing-evidence handoff

对每个核心问题先建立 evidence inventory：现有行为事件、交易/订阅、客服与评论、历史研究、实验、可连接的用户属性，以及相关外部文献、官方统计、竞品/市场材料和标准。记录：

- 哪个问题可被已有数据完整回答、部分回答或无法回答；
- 数据来源、population、时间范围、denominator、关键字段和已知缺口；
- 需要执行的查询、VOC 编码或专项调查，以及对应的可用 skill/tool；
- 输出会删除、改写、新增哪类研究问题，或改变哪些样本和分支。

计划模式只交付这个分析 brief。只有用户要求执行且已具备权限、数据和工具时，才调用相应专项 skill；执行后明确区分实际发现、仍未验证的问题和数据缺口。

不要机械地把所有前置数据分析升级为完整 investigation：已有 dashboard 或单次简单查询能回答时使用轻量路径；涉及多来源归因、可证伪假设或多轮深挖时再路由到结构化数据调查。

## 1.3 Desktop-research routing

桌面调研用于回答“不接触新参与者也能先知道什么”，并发现仍需一手研究验证的缺口。只有结果可能改变研究范围、假设、参与者、问卷选项、刺激材料或方法选择时才执行。

按问题选择来源和专项能力：

| 需要了解 | 优先来源或路由 |
|---|---|
| 竞品功能、价格、定位、行业或技术趋势、标准与合规背景 | 可用时调用 `addx:product-tech-research`；事实优先引用官方产品页、定价页、标准或监管来源 |
| 公开用户语言、痛点、替代方案和竞品反馈 | 可用时调用 `addx:voc-analysis`，并记录平台、时间和样本选择限制 |
| 学术理论、已验证量表、行为规律或方法依据 | 原始论文、系统综述、官方方法文档或权威数据库 |
| 市场规模、人口和宏观背景 | 官方统计或可审查方法的市场资料；供应商估算与事实分开 |
| 组织内部已有认识 | 历史研究、产品文档、客服记录和决策记录，检查日期与当前适用性 |

最低产出不是资料堆砌，而是一份 evidence brief：每条关键发现记录来源、发布日期/数据期、population/geography、来源类型、事实或推断、可信度、对本研究的适用性、设计影响和剩余未知。重要决策尽量使用独立来源交叉检查；营销文案、竞品自述和二手转引不得无标记地当成已验证事实。

桌面调研可以提供候选语言、原因、需求和概念边界，但不能单独：

- 估算自家目标用户中的发生率或需求比例；
- 证明用户能完成任务、会采用、续费或愿意按某价格付费；
- 把竞品存在某功能解释为本产品也应该做；
- 将公开评论样本外推到全部用户。

执行结束后，把结果回填到 decision/evidence inventory：标记哪些问题已回答、哪些只形成假设、哪些仍需访谈、观察、问卷、可用性测试、行为数据或实验。仅制定计划时输出调研问题、来源计划和停止条件，不声称已完成搜索。

## 2. 方法匹配

| 需要的证据 | 合适方法 | 主要限制 |
|---|---|---|
| 已知事实、既有理论、竞品/市场背景、标准与公开语言 | 桌面调研、文献/官方资料、VOC | 来源质量与目标用户适用性；通常不估计自家用户比例 |
| 心智模型、语言、未知原因 | 半结构访谈、情境访谈、开放探索 | 不估计发生率 |
| 实际环境中的行为与约束 | 情境观察、日志、行为数据 | 观察到的行为不自动说明动机 |
| 任务成功、错误与理解 | Moderated/unmoderated usability test | 小样本不能代表全体成功率，除非有合适定量设计 |
| 随时间变化的情境 | Diary study、纵向日志 | 参与负担、遗漏和反应性 |
| 比例、分布、优先级、关联 | Survey、行为数据 | sampling、measurement 和 nonresponse 决定外推范围 |
| 方案相对表现或因果影响 | 随机实验；必要时准实验 | 需要可行干预、指标和足够样本 |
| 方案理解和任务表现 | 中性概念任务、原型测试 | 好感不等于采用 |

方法选择不是互斥标签。问卷中的开放题不等于访谈；可用性测试中的成功率也不自动等于总体比例。

## 3. Mixed-method sequencing

- explore → measure：先访谈/观察建立语言、机制和候选原因，再用问卷估计分布。
- measure → explain：先用行为数据或问卷发现分群/异常，再访谈解释机制。
- prototype → quantify：先确认概念可理解、任务可完成，再估计相对偏好或意向。
- parallel triangulation：方法独立回答同一关键推断时并行；必须提前说明如何处理冲突。
- survey-first conditional follow-up：先估计分布并识别关键分群、矛盾模式或未知答案，再只访谈能改变解释的人。

只有前一阶段结果会改变后一阶段 instrument、sample 或 hypothesis 时才把阶段设成依赖。否则可以并行以缩短周期。

## 4. Minimum research plan

每个核心问题声明：

- research question；
- decision mapping；
- target participant/context；
- selected method 和替代方案；
- participant task/stimulus；
- sample rationale；
- output/estimand or qualitative analytic target；
- decision rule；
- alternative explanations；
- method limitation；
- follow-up evidence。

如结果不能改变任何动作，删除、降为探索性，或说明其风险控制价值。

## 4.1 Instrument handoff gate

当研究计划选定某种参与者研究工具时，交付物不能停留在方法名称。深度随当前决策成熟度和输入完整度递进，不自动进入生产执行。

问卷作为主要方法或重要组成部分时：

| 当前状态 | 最低交付 |
|---|---|
| 方法仍待 owner 确认，或功能、价格、受众等关键输入不足 | 问卷蓝图：业务问题到测量的映射、模块顺序、关键题示例、主要分支、预期负担、样本与分析方式、待补输入 |
| 已确认使用问卷且关键输入充分 | 完整草案：受访者可见文案、全部题目与选项、逻辑、随机化、典型/最长路径、分析映射和限制 |
| 用户明确要求创建、修改、测试或发布线上问卷 | 路由到 survey production workflow，并遵守平台能力、read-back、测试和外部操作授权 |

其他参与者方法采用同一原则：

| 方法 | 研究计划的最低交付 |
|---|---|
| 访谈 | 招募/排除标准、筛选思路、完整提纲、关键追问、记录框架、分析目标与停止依据 |
| 可用性测试 | 参与者起始状态、场景与任务、原型版本、成功/失败标准、提示规则、观察项和严重度口径 |
| 情境观察 | 观察边界、进入/退出方式、记录对象、环境与协作因素、隐私处理和事实/解释分离方式 |
| 日记研究 | 记录触发或频率、持续时间、最小记录字段、提醒/遗漏/退出规则和分析方式 |
| 概念或原型研究 | 要验证的 comprehension/problem fit/usability/commitment、刺激材料、暴露顺序、任务或取舍和禁止推断 |

输入不足时使用占位符并明确待补材料，不编造产品事实。计划无需伪装成已执行研究，但必须让 owner 能判断 instrument 是否真的能回答研究问题。具体材料与执行规则见 qualitative-and-evaluative-methods.md。

## 4.2 Causal boundary and experiment routing

如果核心决定依赖“产品变化是否造成某个行为结果”，普通访谈、问卷、可用性测试或上线前概念偏好不能承担最终因果结论。研究计划只需建立轻量 handoff：

- 要支持的产品决定与可证伪的因果假设；
- 目标用户与目标行为；
- 拟比较的产品变化和当前状态；
- 主要混杂、干扰、伦理或实施风险；
- 为什么现有研究只能形成假设，或为什么需要实验/准实验；
- 应交给哪个实验或数据专项能力，以及进入下一步前缺少什么。

只有用户明确要求实验方案时，才继续定义随机化单位、指标、最小有意义变化、样本/周期、数据质量和分析规则；实际配置、上线或扩大流量是独立外部动作。不要在本通用 skill 内复制实验平台工作流。

## 5. Scope and owner control

Agent 可以合并不改变推断的重复问题、改写 protocol 和建议更合适方法。改变核心范围、目标人群、研究架构、样本投入或证据强度时，展示取舍并由 owner 决定。建议拆 wave 不等于已获准拆分。

## 6. Audience-first delivery

先判断交付给谁、读者要用它完成什么任务，再决定篇幅、词汇和细节层级。不要把某个角色固化为所有研究计划的默认受众。

- 决策者通常需要结论用途、取舍、风险和待确认事项；
- 执行者通常还需要流程、分工、材料和依赖；
- 研究、数据或合规人员需要抽样、测量、分析和治理细节；
- 混合受众优先使用易读主文，并把专业细节放入可选附录；
- 受众不明时，按无专业研究背景的跨职能读者书写，同时保留可审查的技术依据。

这是信息优先级，不是固定报告模板。不要为满足格式重复同一内容，也不要把短建议扩写成完整报告。

### Delivery gate

交付完整研究计划前检查：

1. 目标读者无需翻译术语，能否理解为什么做、要回答什么、怎么做和最终会得到什么？
2. 读者能否找到自己需要决定、提供或执行的事项？
3. 每项重要结果是否说明会支持什么行动，而非只描述研究活动？
4. 是否存在未解释的缩写、英文术语或只对研究人员有意义的标题？
5. 主文是否包含会影响判断的关键限制，同时把不影响当前行动的技术细节放到后面？
6. 简化表达后，是否仍区分行为、态度、预测、相关和因果？

任一关键问题回答为“否”时，先重写交付结构或语言，再交付；不要仅靠添加术语表修补难读的主文。
