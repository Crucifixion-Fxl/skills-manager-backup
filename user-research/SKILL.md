# User Research

## Description

从产品要做的决定出发，选择能提供所需证据且成本合理的方法。不要默认问卷，也不要因为某种方法更容易自动化就改变研究问题。

## Rules

## 1. 选择工作深度

- quick_advice：判断一个研究问题适合什么方法，或审查局部计划；直接回答，不初始化项目。
- research_plan：生成完整研究方案、招募/样本、执行、分析与风险计划。
- mixed_method_workflow：多个方法存在先后依赖，或用户明确要求从探索到验证的完整研究链路。
- execution_coordination：用户明确要求招募、建卷、创建线上研究、发送邀请、监测或报告时，才启用项目状态和外部操作确认。

用户只提出“想知道什么”时，先给最轻可行方案；方法、样本或投入的重大选择需要 owner 决定。

## 2. 研究规划

读取 references/method-selection-and-research-plan.md：

1. 区分 business decision、research question 和 participant task。
2. 提取原始目标、目标用户、已知证据、假设、约束和不能回答的内容。
3. 将范围收敛为会改变不同动作的 Most Important Questions；不擅自删除或拆分 owner 明确目标。
4. 为每个问题定义所需证据、population/context、时间窗口、输出、decision rule 和推断边界。
5. 在访谈、可用性测试、观察、日记、问卷、行为数据、原型与实验之间选择；需要时设计 mixed-method 顺序。

在招募参与者或新增提问前，先盘点已有行为、交易、客服/VOC、历史研究、实验数据，以及相关的外部文献、市场、竞品、公开用户反馈与标准。区分两种状态：

- 仅制定计划：写明需要的数据、要回答的分析问题、口径、输出、依赖和它会如何改变后续研究；不声称分析已经完成。
- 用户要求执行且已具备访问与授权：路由到合适的数据发现、查询、VOC 或专项分析 skill；把实际结果反馈到研究范围、样本和 instrument，而不是把前置分析作为孤立附件。

可靠行为数据已经能回答的内容，不在问卷中要求用户重复回忆；若仍需询问用于解释动机、跨来源连接或覆盖数据缺口，说明用途和局限。

研究方法必须匹配问题：

- 建立已知事实、市场/竞品背景、既有理论、术语或法规约束：桌面调研，并评估来源质量与对目标用户的适用性；
- 探索语言、心智模型、未知原因：访谈、观察或开放式探索；
- 验证任务能否完成及失败位置：基于任务的可用性测试；
- 了解真实情境与长期变化：情境观察、日记或行为日志；
- 估计比例、分布、关联或优先级：问卷/行为数据，并明确 sampling 与 estimand；
- 判断方案造成的因果变化：随机实验或合适的准实验；
- 先发现再估量、或先发现模式再解释原因：按证据依赖安排 mixed methods。

不能用“用户说喜欢”替代行为采用，不能用少量定性样本估计比例，也不能用观察到的相关性声称因果。

## 3. 方法执行

- 桌面调研可能改变研究范围、假设、选项、刺激材料或方法选择时，读取 references/method-selection-and-research-plan.md 的 desktop-research routing。竞品、行业、技术趋势或标准优先路由到可用的 `addx:product-tech-research`；公开评论和社区反馈优先路由到 `addx:voc-analysis`；学术文献、官方统计和规范使用权威的一手来源。不要把桌面调研设为每个项目的固定前置，也不要用外部资料估算自家用户需求比例或代替真实使用/付费证据。
- 问卷是主要方法或重要组成部分时，调用子 Skill `survey-research-workflow`；由它负责构念、问卷结构、选项、平台和答卷链路。完整研究计划不能只写“发问卷”：关键输入不足时至少交付问卷蓝图、关键题示例、分支与分析映射；输入充分且问卷方案已确定时交付完整问卷草案；只有用户明确要求线上执行时才进入平台创建、修改或发布。
- 访谈、可用性、情境观察、日记或概念任务时，读取 references/qualitative-and-evaluative-methods.md。完整研究计划不能只写方法和人数：按方法交付足以评审的招募、参与者任务/提纲、记录和分析材料；只有用户要求执行时才联系或记录真实参与者。
- 用户提供问卷开放题、访谈转录、可用性记录、日记或其他原始研究文本并要求实际分析时，路由到 `user-research-coding`，再把编码包交给报告 skill。公开平台评论仍使用 `addx:voc-analysis`；已有 VOC 编码结果不默认重复编码。
- 所有完整研究计划读取 references/fieldwork-analysis-and-governance.md，明确 sampling/recruitment、分析计划、隐私伦理、包容性、质量监测、版本变化与研究后的 decision closeout。
- 当问题实质是“某项产品变化是否造成行为结果”时，只在研究计划中定义因果假设、目标用户、干预/对照、目标行为与主要风险，并路由到可用的实验或数据专项能力。除非用户明确要求实验设计或执行，否则不在本 skill 展开分流、功效计算、埋点和平台配置；没有实验或合适准实验时，不用问卷意向或观察相关性替代因果结论。
- 有更适合的专项 skill 时优先路由；没有时，本 skill 仍可生成研究 brief、protocol、招募标准、记录模板、分析框架和限制，但不能声称已完成真实参与者研究。

进入 `execution_coordination` 后，按实际渠道路由招募/圈选、邀请发送、回收监测、follow-up 和报告专项 skill。问卷项目沿用 survey-research-workflow 的项目状态与生产契约；其他方法只建立完成当前执行所需的最小状态记录，不把早期 survey-first 版本的重型文件链强加给所有研究。当执行渠道是 Audience Project Personal API（VOC、Typeform、圈人、物化、Brevo 未发送 Draft）时，路由到 `audience-user-research`，不要与方法规划入口 `user-research` 或圈人同步 `audience-sync` 混用。

## 4. 受众适配与默认交付

交付前识别主要受众、他们要完成的任务、已有研究知识和所需细节；不要默认受众一定是 PM、运营或研究人员。受众未说明时，默认写给不具备用研背景的跨职能同事，使用自然、直白的业务语言。

完整研究计划优先按以下信息顺序组织，但不强制使用固定标题：

1. 为什么做、要支持什么决定；
2. 最需要回答的问题，以及研究结束后会得到什么；
3. 推荐怎么做、主要替代方案和投入取舍；
4. 谁参与、如何执行、需要哪些输入或配合；
5. 什么结果对应什么行动；
6. 风险、不能推出的结论和需要 owner 决定的事项。

受众包含非研究人员或多个职能时，采用“易读主文 + 可选方法附录”：主文帮助目标读者理解和行动，抽样依据、测量口径、分析细节与推断限制保留在附录。不能为了易读而删除会改变结论可信度的重要限制。面向研究、数据或合规等专业受众时可以增加技术细节，但仍先说明研究目的与用途。

不要用未解释的术语组织主文。优先写“App 实际使用数据”“客服和用户反馈”“这次最需要回答的问题”等自然表达；确需专业术语时，先用受众能理解的语言解释。`quick_advice` 等短回答无需机械拆分主文和附录。

完整研究计划还需读取 references/method-selection-and-research-plan.md 的受众检查。研究计划应说明“结果会如何改变行动”，而不是只列活动。

## 5. 证据整合

Mixed-method 项目为每条结论记录来源、样本、时间、证据强度与替代解释。不同方法回答不同构念时不能简单“互相验证”；冲突结果先检查 population、情境、时间、测量和选择偏差，再决定是否需要补证。

原始研究文本的主题归纳不在总编排层临时完成。需要编码时保留题目/任务语境和受访者级连接键，使用 `user-research-coding` 输出紧凑编码包；只有数据授权且样本足够时，才把开放题主题与封闭题或行为数据联结。

定性结果报告主题、机制、反例和适用边界，不伪造发生率。定量结果报告 denominator、uncertainty、样本覆盖和分析口径，不把样本描述静默外推到全体用户。

研究完成后区分“研究建议”与“owner 决定”，记录采纳、拒绝、延后或继续验证及其理由、负责人和验证方式。Owner 尚未决定时标记 pending；不能由 agent 自动替代业务决定或未经授权创建后续任务。

## 6. 外部操作与真实性

招募参与者、联系用户、设置激励、录音录像、创建或发布线上研究、上传个人数据、提交测试数据、发送邀请和传播正式结论分别需要授权。Synthetic participant walkthrough 只能发现候选问题，不能冒充真人证据、quote、比例或完成率。

若研究涉及医疗、法律、安全、重大财务、未成年人、弱势人群或不可逆决策，提升伦理审查、真人预测试、数据治理和证据要求。

## Examples

### Bad

产品想了解订阅价值，直接把所有未知问题塞进一份长问卷，并用“愿不愿意购买”替代真实价值证据。

### Good

先明确要支持的定价或功能优先级决定，盘点已有使用与付费数据，再选择问卷估计分布、用少量后续访谈解释未知机制；把不同证据能支持和不能支持的结论写清楚。
