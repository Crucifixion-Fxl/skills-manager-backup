# 研究报告评审流程

评审的目标是发现证据、测量、分析、表达和决策边界中的错误。流程强度应与研究风险匹配，不为所有报告强制安排多角色、多轮会签。

## 1. 基础自审（默认必做）

### 数据与范围

- 样本、快照、排除规则和工具版本是否一致；
- 百分比、人数、分母和跳题是否可核对；
- 每个研究目标是否有结论、状态或证据缺口；
- 是否遗漏不符合叙事但与目标相关的题目或反例。

### 测量与分析

- 题目实际测量的构念是否被正确命名；
- 原始结果与 Net、指数、分档等派生结果是否区分；
- 主要分析与事后探索是否区分；
- 交叉分析、多重比较和模型假设是否合理；
- 关联、预测和因果语言是否越界。

### 表达与行动

- 事实、解释、建议和限制是否易于区分；
- 标题是否比正文证据更强；
- 建议是否说明依据、风险和验证条件；
- 主报告是否可读，证据层是否可追溯；
- 引文是否准确、去标识化且符合使用范围。

## 2. 何时增加独立评审

以下情况建议由另一位具备相应能力的人或独立执行上下文复核：

- 决策不可逆、成本高或涉及重大商业承诺；
- 研究涉及敏感人群、隐私、健康、安全或合规；
- 复杂统计模型、权重、因果推断或大量探索性比较；
- 开放题编码对结论影响大且解释空间高；
- 报告将广泛外传或作为长期基线；
- 研究 owner 与分析者利益冲突明显。

工具或人员不可用时，不要伪造“独立评审已完成”。记录已完成的检查与剩余风险即可。

## 3. 反馈处理

收到评审意见后：

1. 回到原始数据、题目原文或编码证据核实；
2. 判断问题属于事实错误、方法问题、表达歧义、范围争议还是偏好；
3. 修改相关结论及所有依赖它的建议、摘要和图表；
4. 对未采纳意见记录理由，尤其是高风险争议；
5. 重新运行一致性与质量检查。

不要为了迎合评审者而扩大结论，也不要因意见与预期不符就忽略。

## 4. 版本与变更

- 尚未共享的工作草稿可以直接修改，不需要保留删除线历史。
- 已共享、已评审或用于决策的版本，应生成新版本并记录会影响理解或决策的实质变更。
- 被撤回的结论不应继续以删除线留在当前主报告中；在变更记录中说明“原结论、撤回原因、影响范围”。
- 仅格式、错别字或不改变含义的小改动可合并记录。
- Git 历史可以辅助追踪文件变化，但不能替代面向读者的研究变更说明；反之，非代码环境也不强制使用 Git。

## 5. 外部同步边界

报告 skill 可以生成：

- 变更摘要；
- 建议通知对象清单；
- 面向不同受众的同步文案草稿。

除非用户明确授权，不自动发送消息、修改外部文档、发布报告或通知利益相关者。

## 6. 最小复现包

根据风险保留以下材料：

- 数据快照或受控引用；
- 研究工具版本；
- 清洗与排除规则；
- 分析脚本或可复核计算；
- 代码本与引文索引（若有）；
- 最终报告及必要变更记录。

低风险快速发现可以轻量化，但所有对外数字至少要能追溯到数据快照和计算口径。

## 7. 评审完成条件

- [ ] 基础自审已完成
- [ ] 高风险项已获得相称复核，或明确记录未覆盖风险
- [ ] 反馈已逐项核验，而非机械采纳
- [ ] 摘要、正文、图表和附录口径一致
- [ ] 已共享版本的实质变更可追溯
- [ ] 未经授权没有执行外部发布或通知
