# 引文与开放题证据规则

开放题和访谈原话用于解释体验、机制与语言，不应被当作未经抽样控制的总体占比。既要保留受访者声音，也要保护隐私并提供可审计性。

## 1. 优先使用正式编码包

若已有 `user-research-coding` 产物，优先读取：

- codebook 与代码定义；
- 回答—代码矩阵；
- 主题备忘录；
- 分歧、反例和低置信案例；
- 去标识化引文索引。

报告阶段不得为了更顺畅的故事随意合并、改名或删除代码。确需二次归纳时，保留映射关系并说明原因。

没有正式编码包时可以做轻量主题整理，但必须说明材料范围、处理方式、是否多人复核，以及它不能支持什么结论。

## 2. 引文准确性

- 默认逐字引用，不修正语法或改变口吻。
- 为缩短篇幅可用省略号；补充必要上下文可用方括号，不能改变原意。
- 若为可读性做轻度编辑或翻译，应明确标注。
- 不拼接不同受访者的话，不把多条回答改写成一条“典型原话”。
- 报告语言与原文不同时，优先保留可核对的原文与忠实翻译；是否双语展示取决于受众和隐私。

## 3. 可追溯性与隐私

引文必须在受控证据包中可追溯到去标识化记录，但公开或广泛共享的主报告不必展示 respondent ID 尾号。

推荐分层：

- 主报告：角色或情境标签，如“近期流失用户”“家庭共享场景”；
- 受控附录：去标识化引文 ID、题目或访谈位置；
- 原始材料：最小权限访问，保留同意范围和敏感信息处理规则。

不得默认把所有原始开放题答案公开给所有评审者。邮箱、姓名、设备标识、地址、健康信息及可重识别组合必须按数据政策处理。

## 4. 选择引文

每个重要主题可考虑：

- 一条清楚表达常见机制的代表性引文；
- 一条揭示不同情境或反例的引文；
- 一条低频但高风险或高价值的引文（明确标注其稀少性）。

不要只选最戏剧化、最支持建议或语言最漂亮的回答。选择标准应与主题证据一致，并能追溯到编码矩阵。

## 5. 上下文完整性

当一条开放题依赖前序选择、任务或追问时，报告中应保留解释所需的最小上下文。例如：

- 受访者先选择了哪个场景；
- 该题只向哪类人展示；
- 引文是在概念曝光前还是曝光后产生；
- 是自发提及还是从选项中选择后解释。

不要用曝光后的认可回答证明用户在未提示时已有该需求。

## 6. 主题频次

- 分母为实际回答该开放题的人数，除非另有说明。
- 多代码回答可使主题占比合计超过 100%。
- 写“在回答该题的 N 人中，n 人提及”，不要直接写“n% 用户需要”。
- 小样本、短文本或低一致性编码应降低结论强度。
- 主题频次不是主题重要性的唯一标准；严重问题、关键阻碍和新机制可能低频但值得关注。

## 7. 全量材料与附录

是否附全量回答取决于数量、敏感性、同意范围和读者需要，不使用固定条数阈值。

- 少量且低敏感材料：可在受控附录中完整列出。
- 大量材料：提供主题表、引文索引和受控原始数据引用。
- 高敏感材料：只提供必要的去标识化摘录与访问说明。

主报告保持可读，审计材料保持可追溯，两者不必放在同一文件。

## 8. 可视化

开放题可视化应帮助理解结构或关联，例如主题矩阵、路径图、情境×需求表。避免：

- 仅按词频制作词云并把它当作结论；
- 用颜色暗示未被证据支持的好坏；
- 让低频主题因图形面积看起来具有总体代表性；
- 用自动情感分数替代对语境的阅读。

## 9. 最小检查清单

- [ ] 引文可在受控证据中追溯
- [ ] 编辑、翻译和省略没有改变原意
- [ ] 主报告未暴露不必要的身份线索
- [ ] 代表性引文之外还检查了反例和重要少数
- [ ] 自发提及与提示后回答已区分
- [ ] 主题人数与分母正确
- [ ] 开放题没有被夸大为总体发生率或因果证据
