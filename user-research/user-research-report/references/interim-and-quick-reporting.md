# 阶段性报告与 Quick Findings

本文定义何时调用 Quick Findings、它与最终报告的关系，以及问卷仍在收集时必须遵守的边界。

## 三个独立维度

- **用途**：`findings_report`、`decision_support_report`、`recommendation_memo`。
- **阶段**：`interim` 或 `final`。
- **深度**：`quick` 或 `full`。

Quick Findings 表示 `depth=quick`，不是新的用途模式，也不必然表示数据尚未收齐。常见组合：

| 场景 | 默认组合 |
|---|---|
| 问卷发放中的阶段性读数 | `interim + quick + findings_report` |
| 发放中的决策同步 | `interim + quick + decision_support_report` |
| 收集结束后的一页摘要 | `final + quick + findings_report` 或 `decision_support_report` |
| 正式研究报告 | `final + full + findings_report` 或 `decision_support_report` |
| 明确要求业务建议 | 通常为 `final + recommendation_memo`；深度按请求确定 |

## 何时自动调用 Quick Findings

显式请求优先。用户没有指定时，出现以下任一情况，默认使用 `quick`：

- 用户说“quick findings、快速发现、阶段结果、中期快报、当前结果、一页摘要、管理层摘要”；
- 数据仍在收集，用户想知道目前发生了什么；
- 为周会、站会、迭代评审或短周期同步准备材料；
- monitor skill 的一个冻结快照需要转成可读报告；
- 用户需要先看核心结果，再决定是否制作正式完整报告。

以下情况默认使用 `full`：

- 用户要求正式交付、归档、审计、复盘、研究评审或完整报告；
- 需要完整覆盖全部研究目标、全部题目证据和方法；
- 报告将成为长期引用的研究记录。

Quick Findings 只减少可见篇幅，不降低证据门槛。无法在简版中严谨表达的重要结果，应链接到证据层；不能为了短而删除会改变理解的限制。

## 如何判断 interim 与 final

以下任一情况存在时，使用 `interim`：

- 数据收集尚未关闭；
- 目标样本、配额或关键分群尚未完成；
- 数据仍可能因补样、去重、清洗或问卷版本变化而改变；
- 用户明确要求中期、滚动或截至目前的读数。

只有数据收集已关闭或负责人明确冻结本次数据，且口径不再变化时，才使用 `final`。不知道收集状态时先从现有材料查找；仍未知则标注“收集状态未知”，不得擅自称为最终报告。

## Interim Quick Findings 的最低内容

顶部必须醒目标注“阶段性快照，非最终结论”，并包含：

- 数据截止时间、当前有效样本 `n` 与目标样本（如有）；
- 收集状态、问卷/研究工具版本、主要样本或配额状态；
- 完成率、退出、时长、重复答卷、逻辑异常等已有质量信号；
- 当前能直接回答的 3—5 个发现或状态，均给人数和分母；
- 与上一份**可比**快照相比的变化；若口径或版本不同则不强行比较；
- 尚不能判断什么，以及下一次更新应等待的证据。

范围内但当前无足够证据的目标必须显示为“样本不足 / 尚未稳定 / 未测量”，不能因简短而静默消失。

## 滚动查看的安全边界

- 不把阶段性差异称为最终结论，也不以小幅波动制造趋势叙事。
- 不因反复查看数据而无计划地停止收集、扩大显著性检验或挑选最有利切片。
- 除非事先定义序贯分析或停止规则，不依据中途显著性决定提前结束研究。
- 阶段性报告优先描述分布、样本结构和质量；推断统计必须说明重复查看与样本未完成的限制。
- 不用阶段性结果作最终定价、发布或产品取舍；若用户要求临时行动输入，明确写出可逆性、触发条件和未决风险。

## 问卷或研究工具中途变化

若题干、选项、逻辑、抽样或投放发生可能影响测量的变化：

1. 记录变更时间和版本；
2. 变更前后分别保留样本量和分布；
3. 默认分开分析，不直接合并；
4. 只有证明测量等价或变更不影响该指标时才合并，并披露依据；
5. 与历史快照比较时使用同版本、同口径数据。

## 与 monitor skill 的分工

- `user-research-monitor`：获取持续变化的数据、检查回收和质量、形成可复现快照。
- `user-research-report`：读取冻结到某一时点的快照，生成 Quick Findings 或正式报告。

报告 skill 不应自行假定在线表单的实时状态；缺少 monitor 输出时，使用数据中的截止时间，并明确状态来源。
