# User Research Coding

## Description

把原始研究文本转换成可复核的编码数据。优先忠实表达参与者说了什么，再形成解释性主题；不要为了“有洞察”而补全原文没有提供的动机、严重度或用户类型。

## Rules

## 边界与路由

适用于用户已提供或已授权访问的：问卷开放题、访谈/焦点小组转录、可用性与观察记录、日记、客服研究样本及混合方法文本。

- 公开平台评论的采集和既有 VOC 流程继续使用 `addx:voc-analysis`；本 skill 不修改或替代它。
- 只有预先汇总的主题、没有原始文本时，只能审查口径，不能声称重新编码。
- 生成研究报告时把编码包交给 `user-research-report`；本 skill 不把研究者解释写成业务决定。
- 未经授权不上传、传播或复制可识别原始文本；默认处理去标识化副本。

## 工作深度

- `rapid`：低风险探索或少量文本。单一分析者完成语义编码，并复查全部歧义项、无标签项和一部分清晰项；明确不是独立双编码。
- `standard`：默认。先校准 codebook，再编码全量文本；对覆盖主要标签、长尾和边界情况的子集做盲复编码并仲裁。
- `high_assurance`：结果将支持高风险决定、公开主张或精确主题比较时使用。需要独立人工或真正独立的 reviewer；若不可获得则降级结论，不伪称完成独立验证。

同一 agent 清空上下文后重复编码可以检查稳定性，但不等于独立编码者一致性。用户没有要求且风险不高时，不把全部材料双重编码。

## 默认工作流

1. **登记语境**：读取研究问题、原始题干/任务、前序分支、目标人群、语言和数据快照。无法取得关键语境时，限制相关解释而不是猜测。
2. **准备文本**：区分空白、无实质内容和有效回答；长回答按独立含义切成 segment，同时保留 response 归属。去标识化并保存源引用。
3. **建立 codebook**：按任务选择归纳式、演绎式或混合式。每个 code 写定义、纳入/排除标准、相邻边界和例子；先区分描述性 code 与解释性 theme。
4. **校准**：选择能覆盖常见、模糊、反例和长尾的文本校准 codebook。新增或改动 code 后，回编码此前材料，不能让标签含义随批次漂移。
5. **逐条编码**：以语义判断为主，允许多标签。每个标签附原文 evidence span；将“提到某话题”“持何态度”“提出需求”分开。正则或关键词只能作召回、baseline 和回归检查，不能单独决定最终语义。
6. **质量检查**：检查无标签、低把握、多主题、否定/条件句、标签冲突、重复回答、批次漂移和反例。按工作深度复编码并记录分歧与处理。
7. **汇总**：确定性计算主题人数和分母；同一 respondent 在同一主题只计一次，除非预先定义的是 mention 数。区分高频主题、方向性主题、低频重要信号和孤例。
8. **解释**：寻找情境、后果、workaround、期望结果、张力、反例和新问题。行动含义写成研究解释或待验证假设，不伪装成参与者原话。

执行完整编码时读取 [references/coding-package-contract.md](references/coding-package-contract.md)。

## 不可违反的编码规则

- 原始题目和前序语境优先于回答中碰巧出现的关键词。
- 一条回答可以同时表达问题、条件、态度和期望；不要强制单选主题。
- 不能从产品提及推断需求，从情绪词推断严重度，或从写作风格推断用户画像。
- 解释性主题必须能回到描述性 code 和具体 evidence span；合理替代解释存在时保留歧义。
- 低频不等于不重要。低频内容不能冒充普遍需求，但安全、流失、强 workaround、新需求或高后果信号应单独保留。
- 主题频率通常只代表该文本集合或该开放题答题者；不能自动外推到全体用户。
- 翻译可用于辅助理解，但原文是引用与仲裁依据；跨语言 codebook 需要检查语义等价。
- 置信度不能替代复核，也不能用模型自报分数计算“准确率”。

## 最少交付

默认只生成一个 `coding-package.json`，其中包含：

- 数据快照、研究语境和方法；
- codebook 及版本；
- 逐 response/segment 的标签与 evidence span；
- 主题人数、分母、反例和低频重要信号；
- 质量检查、复编码范围、分歧和限制。

只有用户需要单独阅读编码结果时才额外生成 `coding-summary.md`；需要详细仲裁记录时嵌入编码包，除非规模或权限要求单独存放。不要默认复制一份原始文本附件。

## 交付前检查

- [ ] 原始问题、flow、样本和数据快照可识别？
- [ ] codebook 有定义、边界、纳入/排除标准和版本？
- [ ] 每个标签能追溯到 evidence span，提及、态度与需求没有混为一谈？
- [ ] 无标签、歧义、否定、反例、长尾和批次漂移已经检查？
- [ ] 计数单位和分母明确，多标签人数之和不会被误读？
- [ ] 独立复核、同 agent 复编码和人工仲裁被准确命名？
- [ ] 低频信号没有被静默删除，解释没有越过原文证据？

## Examples

### Bad

看到回答里出现“贵”，直接编码为“价格导致流失”，并把提及次数写成全体用户比例。

### Good

分别编码“提到价格”“认为价格偏高”和“明确说因此取消”，保留原文证据、题目语境、受访者分母与反例。
