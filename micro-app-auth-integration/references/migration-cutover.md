# 已有应用迁移与切换

## 适用范围

本手册合并旧 `unified-feishu-auth-migration` 中有效的分阶段迁移、前端生命周期和本地联调经验。旧 Java/Umi 项目的文件名、版本、端口及历史通过数字不是通用契约；旧 Skill 和其四份模板已删除，不保留可执行的兼容入口。

## 1. 盘点与替代链路

- 记录所有登录入口、OAuth 回调、登出、会话刷新、用户注册、API key、后台任务和组织角色的消费者。先区分人类登录与服务身份，不按文件名批量删除。
- 内嵌子应用由主应用提供受控能力，移除重复的飞书登录 UI/流程；独立 Web 应用保留经审查的授权码桥接、state 校验和自身安全会话。
- 按 [SDK 门禁](sdk-integration.md) 固定框架兼容版本、身份来源、授权模式和 Secret 注入路径。缺 SDK/配置时阻塞，不禁用守卫继续发布。
- 替代链路在隔离开发或 staging 中先验证，生产不因配置缺失静默回退旧登录或匿名身份。

## 2. 分阶段切换

| 阶段 | 改动 | 必须保留的证据 |
| --- | --- | --- |
| 基线 | 盘点旧链路、冻结契约、记录已部署版本与回滚目标 | API/身份/资源矩阵及所有未核验项 |
| 接入 | SDK 认证和权限守卫、平台能力 adapter 或授权码桥 | 编译、依赖兼容、401/403/503 和真实允许/拒绝 |
| 切换 | 在同一受控版本启用替代链路并移除重复认证 | 路由/接口调用者、旧会话处理、权限变更与回调测试 |
| 清理 | 删除无消费者的旧类、接口声明、import、页面、配置和秘密引用 | 无悬空引用、完整测试；不删除仍服务 API token/后台任务的逻辑 |
| 发布 | 走仓库既有部署链路，核对环境、区域、namespace、GitOps revision | 精确 SHA/digest、配置版本与运行时验收 |

每阶段编译并运行相关测试。编译通过不代替安全验收；测试编译失败要修复测试，不把跳过测试参数当成通过。

## 3. 前端与联调

生命周期和能力 adapter 统一使用 [实施手册](implementation-playbook.md)，不再维护另一套 raw token 请求封装。

- 核对 Umi/Vite/Webpack 的实际构建插件后再设置 public path、router basename 和生命周期；不要跨框架复制配置。
- mount 时使用应用容器，unmount 清理 React root、监听器、定时器、订阅及缓存的用户信息。主应用能力缺失时生产安全失败。
- 仅显式 dev adapter 可使用合成身份，不在全局对象存储 token，不自动匿名降级，不向未登记 origin 附带凭证。
- 本地 Compose 按应用实际依赖选择基础设施、平台、应用与网关；健康检查及启动依赖用于排障，不构成认证或授权通过证据。
- 网关验证路径重写、context path、DNS、Cookie/CORS/CSP。区分匿名静态 entry 与携带凭证的业务 API，凭证接口不使用通配 CORS。
- GraphQL 按 schema 和 transport 发真实请求并检查 errors；HTTP 200 或 HTML 中存在 qiankun 标记均不代表权限已验证。
- 原生依赖构建失败时核对支持的 runtime、架构和 libc，不固定套用旧模板的 Node 版本或禁用测试。

## 4. 身份与审批切换验收

按 [验证清单](validation-checklist.md) 收集证据，额外覆盖已有账号迁移：

- 身份使用权威的租户范围内稳定 ID；不得以姓名合成邮箱进行账号合并。不同身份已绑定同一邮箱时拒绝隐式关联并走受控核验。
- 平台明确禁用的身份在初始登录和续期均被拒绝；依赖故障不作为身份有效的依据。核对消费者实际使用的会话校验端点。
- 普通申请者不能控制外部授权目标或服务端回调关联。由受信入口绑定申请者、应用、资源、外部请求 ID 和回调；审批者权限必须覆盖实际被授予的目标。
- 回调按完整 scheme/host/port/path boundary 校验。只有平台明确批准的内网契约才允许受限 HTTP，不能泛化允许所有私网地址；同时验证发送方实际解析 URL。
- 审批决定与待投递事件可靠落库，投递失败有持久化重试、幂等、告警和受控重放。分别记录审批通过与授权生效，并验证故障恢复。
- 原生组织/角色模型需要显式映射和受控执行边界；普通业务应用不能自行批准自己的权限申请。

## 5. 回滚

分别记录代码/镜像、GitOps 配置、Secret 版本和权限数据的回滚策略。不得回滚到已知 fail-open 实现，也不为恢复访问临时关闭认证。旧会话应撤销还是自然过期必须显式决定；代码回滚不会自动撤销已授予成员或重放丢失审批，数据修复需单独审计与授权。
