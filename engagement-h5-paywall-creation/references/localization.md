# Paywall 多语言交付与验收

## 文案与语言清单

- 从当前语言契约和投放范围固定目标语言/别名；未限定时采用项目全部支持语言。不能因为只有英文设计稿就只交付英文。
- 按实例、页面/状态列出可见文案及 aria-label/alt：标题、卖点、商品卡/标签、CTA、挽留/All Plans、试用时间线/提醒、法律入口、加载/错误/重试、购买与恢复状态。检查代码中的默认文案、动态 key 和 CMS/实例资源；图片含文字时另列素材语言。
- 优先复用语义一致的已存在词条和术语；不同的商品范围、优惠或权益承诺不能为复用而改义。新增译文记录来源和审核状态。

## 必须通过的轻量检查

1. 每个被引用的 key 在每个目标语言中均存在且非空；动态 key 必须展开周期、复数及状态分支。检查实际生效资源，不能只检查未加载的 `locales.ts`，不能在完整性检查前用英文合并补齐缺口。
2. 对比命名占位符集合，检查动态文案无未替换 `{name}`/`$name`/`%@`；插值参数只提供真实金额/币种/周期等事实。主语、语序、连接词和计费说明由整句模板决定。
3. 在真实渲染路径验证宿主语言规范化、资源加载和有效文案。支持语言缺词条导致英文 fallback，判失败；未支持语言的兼容 fallback 单独测试。品牌名、ISO 币种、合法术语及两种语言本来相同的词可保留，但须逐项有依据，不能把“与英文相等”一律通过或一律失败。
4. 试用、促销首期、首期次数/总额、续费和一次付费都检查整句及单位。不得拼英文 `for/then/total/mo`，不得把月付、两个月优惠和两个月一次收费混为一谈；按 quote 的周期与 recurrence 展开。
5. 用 static/unit/component 做 key、占位符、实际加载和计费回归；不为每个语言/业务模板重复底层支付 E2E。已有检查未覆盖缺口时补最小确定性回归，不增加只有“包含金额”而无法发现英文回退的断言。

## 截图与结论

- 自动词条检查覆盖全部目标语言；整页截图至少覆盖英文、简体中文（支持时）、长文案语言及 RTL（支持时）。受影响的每种布局/用户分群/设备档位和独立挽留/All Plans 页均检查；未跑组合如实列出。
- 中文验收检查整页，包括法律入口、计费摘要、试用提醒和错误态，不能只看标题/CTA。长文案检查换行、截断、按钮/价格遮挡；RTL 检查方向、金额与混排。
- 保存实例 ID、源 SHA/制品、请求与规范化语言、页面/状态、viewport/平台、词条结果及截图路径。浏览器数据标明 mock/live，浏览器截图不代替真机；不覆盖历史证据和已批准 baseline。
- 词条齐全不代表译文已获专业审核；金额正确不代表本地化通过。语言失败时列 `LOCALIZATION_FAILED` 及 key/语言/状态；缺少执行证据写 `NOT_RUN`，不得声称 UI/UAT 完成。
