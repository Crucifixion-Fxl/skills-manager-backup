# 画像筛选

使用当前 Project 的 `get_query_capabilities` 响应作为可执行字段目录。
其中公布逻辑关系、字段、值类型、操作符和边。[已审阅基线](project-query-whitelist.md)帮助理解已知字段，不能覆盖在线能力。

- 先匹配用户要求的业务含义，再选择字段。例如，当前订阅状态与最近一次订阅取消是不同概念，不能互相替代。
- 保留公布的值类型。即使某些值看起来像数字，字符串字段仍是字符串；只使用该字段公布的操作符。
- 日期与时间条件须明确业务区间和时区，再使用字段契约接受的时间戳格式及操作符。
- Platform 会在创建的圈人计划中冻结画像分区。若与用户要求有关，应展示返回的数据新鲜度与分区证据。
- 只有在线能力公布了对应边和量词，扩展关系或 join 才可用。DataHub 可为接入提案提供发现证据，不授权可执行路径。
- profile 始终是成员主表，由 Platform 施加当前 Project 的 tenant+bundle 筛选；
  已审阅的 user-scoped 子表通过全局 `user_id` 直接关联，不强制子表具有 tenant/bundle。
  因而子表事实可能跨业务，不能默认为当前 bundle 内的订阅或行为；先确认用户需要的业务口径。
  旧直接隔离关系仍按 registry 保留额外限制，Agent 不注入或删除范围条件。
- 若需聚合，使用在线边已公布的命名指标。缺少边、字段或指标时提出 Audience 白名单接入需求；
  不能仅因为子表没有 tenant/bundle 或需要 COUNT/SUM/MIN/MAX/AVG 就要求 DATA 建模。
  只有来源或所需转换语义不存在、或当前能力不能表达时，才说明需要上游建模评估。
- 默认使用生产能力，不自动向其他环境探测或回退。离线契约或 MR 不证明在线已部署；
  若能力未公布对应指标，保持不支持，不跳过验证提交。

[圈人条件](audience-filter.md)说明请求构造方式。明确报告不受支持的条件。
预览返回聚合证据；成员行、物理身份列和收件人标识留在 Platform 内。
