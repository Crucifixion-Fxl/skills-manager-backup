# 配网与本地访问：代码审查执行摘要

正本：[固件配网与本地访问安全审查规范](../../../public/dev-standards/firmware/device-access-security.html)。
固件产品提交审查时主动核验目标版本的安全实现；即使只改业务逻辑，也必须查未改动的基线缺口。B/F 是检查项索引，风险仍关联 S1–S10 和既有 RL，不另造产品专属红线。

## 0. 提交时主动检查缺失实现

按正本执行以下必查最小集合，并继续覆盖原有 S1–S10 相关规则。先从产品构建与入口确定功能是否适用，再找实际保护路径；不能因为没有安全函数名或没有改动安全文件就跳过。目标为候选 SHA 的有效实现，跨到实际 SDK、BSP、产线注入与构建 profile；获取不到的部分保留待核验，不写通过。

取证遵守当前环境与上游约束：已授权本地审查可读取相关完整源码；受限 CI 只使用 review-data 和上游允许的 helper，不能自行取未修改文件全文。路径存在性、完整变更清单均不能代替实现证据。保留缺材料的 B/F 项为待核验，继续报告已有证据支持的问题；具体边界见 skill Step 0.5。

| 技术项 | 必须识别的缺失/失效实现 | 修复与验收方向 |
|---|---|---|
| B01 串口登录/每机凭据（S4/S8/S10） | 直接/自动 shell、共用默认口令；完整出厂链路未生成注入每机凭据；注入失败仍放行 | 关闭非必要入口；需要密码登录时采用每机独立、不可预测的强凭据，生成/注入/读回闭环、失败拒绝、维护权限与尝试限制；具体 hash 不明则强度待核验 |
| B02 ADB（S8/S10） | 默认调试暴露，主机认证未启用/无效，未知主机可进入 shell/sync，维护权限过宽 | 生产默认关闭与受控开启；验证未知主机拒绝、授权/撤销、实际进程和文件权限；已有认证不能掩盖默认开启策略缺口 |
| B03 USB/RNDIS HTTP（S10） | 产品要求禁用时，USB 网卡 + HTTP 监听 + 路由/防火墙仍形成访问路径 | 按要求移除功能、限制绑定或阻断流量；核验 IPv4/IPv6 与各启动模式；**已有鉴权仍不等于禁用了路径** |
| B04 TCP 调试/产测（S10） | 不必要或未授权调试监听，独立产测服务绕开主应用开关，固定帧头/时间窗代替认证 | 移除非必要入口；其余受控开启及鉴权。分别描述回环与外部网络的到达条件，不能把回环直接称为公网入口 |
| B05 安装内容校验（S2/S5） | 只比大小/版本/元数据，没有计算真实安装内容摘要；摘要不匹配仍安装 | 计算实际使用的载荷并校验可信期望值，失败停止；通过损坏内容案例验收；签名、防回滚继续独立检查 |
| B06 BLE（S3/S4/S10） | 固定/可预测会话值，随机失败回退，身份/命令权限/重放保护缺失，稳定广播身份 | 可靠随机源及失败拒绝；有效配对与会话认证、命令授权、失效和隐私检查；不能只修随机性就关闭整项 |
| B07 Wi-Fi 凭据（S3/S4/S8） | 固定/公开信息派生，未持久化，读失败回退默认值，解绑后 AP/responder 缓存旧值 | 随机、存储、实际应用与缓存一致；覆盖错误、重启、解绑与恢复出厂；与系统密码分项 |
| B08 日志/状态输出（S8） | 启动、状态、错误、调试日志或诊断输出长期密码/token | 输出前移除/脱敏；覆盖所有分支；用合成秘密验证，不读取或打印真实凭据 |
| B09 恢复出厂（S8） | 无清除、遗漏主备、失败仍成功、重启恢复旧数据 | 明确用户数据/凭据/密钥范围，处理错误及恢复；逐项故障验证，不把逻辑删除称不可恢复擦除 |
| B10 中断恢复（S5/S8） | OTA/关键 NV 写入中断后不可恢复，或恢复回不安全默认值 | 平台适用的原子更新/备份/槽位和启动确认；覆盖关键中断点；恢复不绕过认证/验签/版本策略 |
| B11 输入边界（S8/S10） | 路径越界，长度/索引/整数检查缺失，或先复制后检查 | 操作前完成规范化和范围检查；覆盖边界、越界、错误路径，不以检查函数存在证明生效 |
| B12 文件/诊断授权（S8/S10） | 读取前无身份或资源权限，客户端可开启敏感收集，创建/下载任一阶段绕过 | 统一认证/资源权限，白名单与脱敏；逐入口验证拒绝路径 |

流程另列：F01 必要静态分析/测试/覆盖与失败阻断；F02 CI 凭据传递、泄漏与权限；F03 固件登记请求认证/完整性/失败行为（HMAC 是具体实现之一）；F04 制品哈希、源码/依赖/BSP 绑定及分支来源校验。各项都检查“完全未做”，不是只有找到工具配置或 HMAC 函数才检查。无需指定某个扫描工具品牌，也不以流程控制代替设备实现。

每项给出状态与证据：已实现 / 部分实现 / 缺失或失效 / 待核验 / 不适用。缺失须追到实际调用/配置及其前置保护，未搜索到函数名不足以证明缺失；不适用须有产品或构建证据。允许引用同一目标版本仍有效的基线记录，发生相关实现/依赖变化必须重新核验。

先输出当前缺口，再标本次引入/扩大、已确认既有或归因待核验。旧缺口按原 MR 门禁处理，**仍须列出且产品基线不能通过**；证据不足也不能通过。不把未来计划或别的分支修复直接当作目标版本的有/无实现证据。

## 1. 固定证据范围

- 记录目标分支和完整 SHA、子模块 SHA、下载依赖版本/哈希、BSP、build profile；只判断目标版本实际采用的实现。
- 搜索历史后回到目标 SHA 核查加入、修改和撤回。提交标题、changelog、其他分支和测试名称都不能代替实现证据。
- 标出证据层级：源码 / 构建配置 / 成品镜像或二进制 / 实机。某层未取得就注明该层待核验，继续其他检查；不将未知写成未实现。
- 不因未知 SOC、RAM 或 TLS 库停止独立的只读认证/数据流检查；只暂缓依赖该信息的方案选择。

## 2. 对每个入口追踪完整调用链

`启动/监听 → 可达条件 → 状态与时间窗 → 调用者认证 → 操作/资源授权 → 实际读写/执行 → 进程权限`

USB 上的 ADB、RNDIS HTTP、产测 TCP 和串口协议分别检查。一个协议已认证不代表其他协议继承其保护。固定帧头、设备 ID、已绑定状态和短时间窗均不能单独证明调用者身份。配置关闭一个服务，仍要核对其他启动脚本和依赖模块。

## 3. BLE 配网（S3/S4/S10）

追踪随机源与错误返回、会话值生成/更新、首次交付渠道、设备与手机身份验证、命令会话绑定、完整性与重放保护，以及解绑/重绑/掉电后的失效。核查 BLE 栈/MCU 的实际配对与 GATT 访问权限，不能只查应用 token 函数。

- 随机 token 只关闭固定值子问题。若任意连接者均能取得，或仅用可公开还原的 XOR 传输，不能判定身份认证或保密已完成。
- 追踪绑定、解绑、配置、控制等各命令；LOGIN 分支有检查不证明其他分支也检查。
- 广播同时查地址和载荷；地址轮换不能抵消载荷中的稳定 SN。配网窗口与认证分开评价。
- 修复：落实既有 BLE 配对安全基线；应用层需要额外证明设备/所有者身份时，采用经审查的认证密钥协商，将操作绑定有效会话并检查权限，采用认证消息保护与防重放，按产品需要限制可连接状态及稳定标识。应用层措施不自动豁免既有 BLE 链路规范。

## 4. Wi-Fi 凭据（S3/S4/S8）

SoftAP 密码、用户路由器凭据、P2P/WPS 临时凭据、BLE 会话值和系统账户密码分别列项。检查生成、保存、读取、应用、缓存、轮换、解绑、重启及日志/诊断。

- CSPRNG 或读取/写入失败是否被处理；是否回退固定口令；已生成新值是否真的被 AP 与配网 responder 使用。
- 密码保存成功但 responder 缓存旧值，属于轮换一致性问题；承认随机性措施，单独指出残余缺口。
- 修复：CSPRNG 或受保护设备秘密 + 标准 KDF；SN 只作上下文。更新失败保留明确旧状态或停止宣告就绪；保存、实际应用和缓存一致；按目标平台保护存储并脱敏导出。

## 5. ADB 与系统登录（S4/S8/S10）

检查启动、profile、属性配置的生效链及精确 adbd 实现/二进制；验证 USB/TCP 的认证、信任公钥来源、未知主机失败路径。另查 shell/sync、启动 UID/GID、降权和文件范围。

- `adb shell` 不问密码不等于未认证：该电脑可能已持有受信任主机私钥。`bash -l` 不等于 `/bin/login`。
- 分开描述：调试默认开启策略、主机认证、认证后权限、系统账户密码。公钥不是泄漏的私钥；核查授权范围、私钥保管与撤销。
- 账户存在、允许的 shell、哈希/锁定字段、产线替换分别取证。只有预置哈希不能断言固定弱密码；有限常见密码比对未命中也不能证明密码强。
- 修复：生产默认关闭，维护按授权临时开启并可撤销，限制认证后权限。实际需要密码登录时独立管理维护账户和每机凭据；不能用 Wi-Fi 随机密码证明 root 每机密码已实现。

## 6. 文件、诊断与产测（S8/S10）

- 路由注册 → middleware/认证回调 → handler → 数据来源逐层查，授权必须先于读取/写入/执行。路径和文件 ID 检查不等于资源访问授权。
- 查诊断创建、敏感选项、实际收集清单和下载。`include_sensitive=false` 默认值不能抵消未授权请求可改为 true。
- 准确写影响范围：固定资源、目录内文件或任意路径；未见任意文件证据时不得扩大。
- 查外部输入到 `system`/`popen`/shell/`exec` 的数据流。仅返回文件元数据不能写成已返回文件内容。
- 修复：统一认证与操作/资源授权；诊断白名单和脱敏；产测独立认证及受控时间窗；优先库调用或独立 argv，配合参数/下载目标限制，避免拼接 shell。
- CORS 单列：通配符属于公司策略缺口。跨站读取还需核对网络可达性、浏览器限制、方法/预检、凭据模式和可读响应；跨站控制/写入另查请求能否发出及产生副作用，响应不可读不代表操作未执行。CORS 收紧不替代接口认证或 CSRF 防护。

## 7. 局部措施与流程状态

- OTA 分开核查实际内容摘要、摘要可信来源、设备端签名、防回滚和断电恢复。包内摘要、CI 登记 HMAC 或 A/B 回退不能代替设备端验签/最低安全版本策略（S5）。
- 存储区分持久化、CRC/XOR/编码、认证加密、逻辑清除和不可恢复擦除；查主备副本、失败返回、重启恢复。修复失败不报成功，未验证效果不宣称安全擦除（S8）。
- 流程单列 CI/SAST/Sanitizer/SBOM/制品追溯的范围、跳过条件、失败是否阻断、正式包是否必经及运行记录；配置存在不等于执行通过。产品 ELF 保护以该制品为证据。

## 输出与验证

每项写：`检查项 | 要求来源/适用条件 | 优先级 | 目标版本 | 实现状态 | 文件:行号及证据层级 | 触发条件/影响 | 修复方案 | 验证办法`。技术与流程分列；未实现和待核验项均保留；已完成子问题与剩余缺口分开。产品基线状态与本次 MR 增量结论分别给出。

Bad：有随机 Wi-Fi 密码，因此账户一机一密；ADB 开启，因此任何人免认证 root；SHA-256 校验，因此已验签。

Good：分别验证每类凭据和调用链，只关闭证据实际覆盖的子问题，再给出剩余缺口的修复及验证办法。

验证输入见 [evals.json](../evals/evals.json)。格式校验不代替模型行为评测；报告实际执行了哪些验证。
