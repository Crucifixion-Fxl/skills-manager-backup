## ETSI EN 303 645

ETSI EN 303 645 是消费级 IoT 设备的网络安全基线标准，覆盖 13 条基本安全要求。以下逐条映射到 A4x 固件实现。

### 条款映射

| 条款 | 要求 | A4x 实现 | 固件关注点 |
|------|------|----------|------------|
| 5.1 | 无通用默认密码 | 每台设备工厂预置唯一凭证 | 设备 ID + 证书预置，禁止硬编码公共密码 |
| 5.2 | 实现漏洞披露管理 | security@addx.com + CVD 流程 | 固件版本号可查询，支持远程诊断 |
| 5.3 | 保持软件更新 | OTA 签名验证 + 防回滚 | ECDSA/Ed25519 签名、版本单调递增、安全计数器 |
| 5.4 | 安全存储敏感参数 | eFuse/SE/TEE 密钥存储 | 设备密钥不可通过调试接口读出 |
| 5.5 | 安全通信 | TLS 1.2+ 全链路加密 | mbedTLS 配置、密码套件、证书管理 |
| 5.6 | 最小化暴露攻击面 | 关闭未用服务和端口 | 生产固件禁用 debug 串口、telnet、未认证 HTTP；设备本地接口鉴权与暴露面按 SKILL.md **S10**（红线 RL-12–RL-15）逐接口核 |
| 5.7 | 确保软件完整性 | Secure Boot 信任链 | Bootloader 验证固件签名后才启动 |
| 5.8 | 确保个人数据安全 | 视频 E2E 加密 + 零知识架构 | 云端不持有解密密钥，传输全程加密 |
| 5.9 | 系统对中断的恢复力 | 本地缓存录像 + 自动重连 | OTA 失败回滚到旧版本，看门狗恢复 |
| 5.10 | 检查系统遥测数据 | 异常行为检测 | 固件可上报异常登录尝试、异常流量模式 |
| 5.11 | 方便用户删除个人数据 | 恢复出厂 + 云端数据删除 | 恢复出厂设置清除所有用户数据和密钥 |
| 5.12 | 方便设备安装维护 | BLE 配网 + 自动更新 | 零配置安全（用户不需要手动设置安全参数） |
| 5.13 | 验证输入数据 | 严格解析所有输入 | 命令/配置解析有长度限制和格式校验，防止缓冲区溢出 |

## EN 18031 — EU RED 网络安全协调标准

EN 18031 是 EU Radio Equipment Directive (RED) 的网络安全协调标准，**2025 年 8 月 1 日起强制执行**，产品进入 EU 市场必须合规。分三部分，28 条核心要求跨三部分通用。

### EN 18031 vs ETSI EN 303 645

| 方面 | EN 18031 | ETSI EN 303 645 |
|------|----------|-----------------|
| **法律效力** | EU RED 协调标准，合规即推定符合 RED | 自愿最佳实践，无法律约束力 |
| **适用范围** | 所有联网无线电设备（手机/路由器/摄像头/穿戴） | 仅消费级 IoT |
| **强制日期** | 2025-08-01 | 无 |
| **结构** | 3 部分（网络/数据/反欺诈） | 单一标准 13 条 |
| **评估方式** | 基于资产的风险评估 + 决策树 | 条款检查 |

### EN 18031-1: 网络保护 (RED Art. 3.3d) — 31 项要求

设备不得危害或损害网络，11 个要求组：

| 要求组 | 关键要求 | A4x 固件实现 | 对应安全域 |
|--------|----------|-------------|-----------|
| **访问控制** | 设备访问限制，基于资产保护 | 设备唯一凭证 + BLE 配对认证 + 云端 token 认证 | S3, S4 |
| **认证** | 用户/实体身份验证，禁止默认密码 | mTLS 设备证书 + App 认证 + 禁止通用默认密码 (RL-06) | S3 |
| **安全存储** | 静态敏感数据保护 | AES-GCM 加密 Flash 凭证 + eFuse/SE/TEE 密钥存储 | S4, S9 |
| **安全通信** | 认证性、机密性、防重放 | WSS/HTTPS TLS 1.2+ + WebRTC DTLS-SRTP | S3 |
| **韧性** | 可用性与容错 | 硬件看门狗 + OTA 回滚 + 异常自恢复 | S5, S6 |
| **网络监控** | 流量分析与异常检测 | 异常登录检测 + 异常流量模式 + 安全事件上报 | S3 |
| **流量控制** | 防止网络资源耗尽 | 连接限速 + 速率控制 + DoS 抗性 | S3 |
| **密码密钥 (CCK)** | 密钥生成/存储/生命周期 | TRNG + eFuse + HKDF + 安全清零 | S1, S2, S4 |
| CCK-1 | 使用适当的密码密钥 | AES-128/256 + ECC P-256 | S1 |
| CCK-2 | 密钥生成机制 | TRNG 硬件随机数 (RL-07) | S1 |
| CCK-3 | 禁止静态默认值 | 每台设备唯一密钥 + 禁止默认密码 (RL-06) | S4 |
| **密码学** | 现代算法和模式 | AES-GCM/CCM + SHA-256+ + 禁止 MD5/SHA-1 (RL-02) | S1, S2 |
| **安全更新** | 多机制保护 (条款 6.3.2.4) | 签名验证 + HTTPS + 设备身份访问控制 + 防回滚 | S5 |

**条款 6.3.2.4 安全更新 4 类保护机制**（EN 18031 要求组合使用，单一机制不足）：

| 类别 | 机制 | A4x 实现 |
|------|------|----------|
| 1. 数字签名 | ECDSA/Ed25519 固件签名验证 | ✅ ECDSA P-256 |
| 2. 安全通道 | 加密传输通道 | ✅ HTTPS (TLS 1.2+) |
| 3. 访问控制 | 限制谁可发起更新 | ✅ 设备身份认证（mTLS/token） |
| 4. 其他机制 | 补充验证 | ✅ 版本防回滚 + 安全计数器 |

### EN 18031-2: 数据与隐私保护 (RED Art. 3.3e) — 40 项要求

适用于处理个人数据的联网设备（摄像头必须合规）：

| 要求 | 说明 | A4x 固件实现 | 对应安全域 |
|------|------|-------------|-----------|
| 默认访问控制 | 限制第三方访问个人数据 | 视频 E2E 加密 + 零知识架构 | S7 |
| 数据最小化 | 只收集必要数据 | 固件不采集非功能必需的用户数据 | S9 |
| 传输加密 | 个人数据传输保护 | TLS 1.2+ 全链路 + 视频 SRTP | S3, S7 |
| 存储加密 | 个人数据存储保护 | SD 卡视频加密 + Flash 凭证加密 | S9 |
| 用户删除权利 | 支持用户删除个人数据 | 恢复出厂设置擦除所有用户数据 (RL-10) | S9 |
| 访问日志 | 记录数据访问 | 安全事件上报云端 | S9 |
| 儿童数据保护 | 儿童看护设备特殊保护 | 如适用：加强认证 + 限制数据共享 | S9 |

### EN 18031-3: 反欺诈 (RED Art. 3.3f) — 34 项要求

## NIST 网络安全指南

### NISTIR 8259 — IoT 设备安全能力基线

NISTIR 8259 定义了 IoT 设备应具备的核心网络安全能力：

| 能力 | 要求 | A4x 固件实现 |
|------|------|-------------|
| **设备标识** | 设备有唯一逻辑标识 | Device ID + X.509 证书（CN/SAN 绑定） |
| **设备配置** | 可配置安全相关参数 | 加密开关、TLS 配置可通过安全管理通道调整 |
| **数据保护** | 静态和传输数据加密 | AES-GCM/CCM 存储加密 + TLS 传输加密 |
| **逻辑访问控制** | 只有授权实体可访问 | mTLS + 基于证书的身份认证 |
| **软件更新** | 安全的更新机制 | OTA 签名 + 防回滚 + HTTPS 传输 |
| **网络安全状态感知** | 报告安全相关事件 | 异常事件上报（认证失败、异常访问） |

### NIST SP 800-183 — 物联网网络

核心安全原则映射：

| 原则 | 固件层面的实现要求 |
|------|-------------------|
| 最小权限 | 固件模块间权限隔离，密码操作在独立模块 |
| 纵深防御 | TLS + 应用层加密 + 安全存储 + Secure Boot 多层防护 |
| 最小信任 | 验证所有外部输入（云端命令、App 指令、OTA 包） |
| 安全默认 | 出厂即启用安全功能，无需用户手动开启 |
| 失败安全 | 加密/认证失败时拒绝操作，不降级到不安全模式 |

### NIST CSF 五功能框架

| 功能 | 固件层面的关键活动 |
|------|-------------------|
| **识别 (Identify)** | 设备资产清单、密码算法清单、通信端口清单 |
| **保护 (Protect)** | 加密、认证、Secure Boot、访问控制 |
| **检测 (Detect)** | 异常登录检测、固件完整性自检、TRNG 健康监测 |
| **响应 (Respond)** | 安全事件上报、异常连接断开、密钥吊销 |
| **恢复 (Recover)** | OTA 失败回滚、恢复出厂设置、备份启动分区 |

## FIPS 140-2/3 考量

### 何时需要 FIPS

- **US 联邦政府客户**：明确要求 FIPS 140-2 Level 1 或以上
- **US 国防/情报客户**：可能要求 FIPS 140-2 Level 2+
- **A4x 消费级产品**：默认**不要求** FIPS（文档记录为豁免）

### FIPS 对固件的影响

| 方面 | 非 FIPS（默认） | FIPS 模式 |
|------|-----------------|-----------|
| 密码库 | mbedTLS | wolfSSL FIPS 模块 |
| 算法限制 | A4x 规范 | FIPS 批准算法列表 |
| 自检 | 基本 TRNG 检查 | 开机密码算法自检 (POST) |
| 密钥处理 | 安全清零 | 密钥安全清零 + 物理保护 |
| 随机数 | TRNG + CTR-DRBG | FIPS 批准的 DRBG + 连续测试 |
| 认证成本 | 无 | FIPS 认证费用 + 时间 |

### FIPS 批准算法列表（摘要）

| 类别 | 批准算法 | 说明 |
|------|----------|------|
| 对称加密 | AES (128/192/256) | 所有标准模式 |
| 哈希 | SHA-2 (256/384/512), SHA-3 | MD5、SHA-1 不批准 |
| MAC | HMAC, CMAC, GMAC | |
| 签名 | RSA (>= 2048), ECDSA (P-256+), EdDSA | |
| 密钥交换 | ECDH (P-256+), DH (>= 2048) | |
| KDF | SP 800-108 KDF, HKDF | |
| DRBG | CTR-DRBG, HMAC-DRBG, Hash-DRBG | 必须 FIPS 批准的 DRBG |

### wolfSSL FIPS 集成

选择 FIPS 模式时使用 wolfSSL 替代 mbedTLS：

- wolfSSL FIPS 模块已通过 FIPS 140-2 Level 1 认证（CMVP #3389 等）
- API 与 mbedTLS 不兼容，需要适配层
- 固件应设计密码操作抽象层 (Crypto HAL)，支持运行时切换 mbedTLS / wolfSSL
- FIPS 模式要求开机执行 Power-On Self Test (POST)：AES KAT、SHA KAT、DRBG 测试

## Matter 协议安全

### 何时需要 Matter

- 产品需要 Matter 认证（CSA 认证标志）
- 需要与其他 Matter 设备互操作（Apple Home、Google Home、Amazon Alexa 原生）
- A4x 摄像头可能以 Matter Bridge 模式接入 Matter 网络

### Matter 安全要求

| 安全机制 | 说明 | 固件实现要求 |
|----------|------|-------------|
| **CASE** | Certificate Authenticated Session Establishment | 设备间使用 NOC 证书建立加密会话 |
| **PASE** | Passcode Authenticated Session Establishment | 配网阶段使用 SPAKE2+ 协议 |
| **AES-128-CCM** | Matter 消息加密 | 强制使用 AES-128-CCM（不可替换为 GCM） |
| **DAC** | Device Attestation Certificate | 工厂预置，证明设备真实性 |
| **NOC** | Node Operational Certificate | 加入 Fabric 后由 Commissioner 签发 |
| **CD** | Certification Declaration | 声明设备已通过 Matter 认证 |

### DAC 证书链

```
PAA (Product Attestation Authority)
└── PAI (Product Attestation Intermediate)
    └── DAC (Device Attestation Certificate)
         - Subject: 设备信息
         - Key: P-256 密钥对
         - 预置于工厂产线
```

- DAC 私钥**必须**存储在安全存储中（与设备证书私钥同等保护）
- PAI 证书通过 DCL (Distributed Compliance Ledger) 可查验

### Matter + 摄像头的安全边界

A4x 摄像头以 Matter Bridge 模式接入时：

```
Matter Fabric (Thread/WiFi)
    ↕ [Matter CASE 加密]
A4x 摄像头 (Matter Bridge)
    ↕ [MQTT TLS / WebRTC DTLS-SRTP]
A4x Cloud
```

安全边界：
- Matter Fabric 内通信使用 Matter 的 CASE 加密（AES-128-CCM）
- 摄像头到 A4x 云的通信使用 A4x 自有的 TLS/SRTP 加密
- 两个加密域独立，Bridge 负责安全转换
- 视频流**不经过** Matter 通道（带宽限制），仅控制命令走 Matter

## IEC 62443 工业安全

### 何时适用

- A4x 企业/工业摄像头部署（工厂、仓库、关键基础设施）
- 客户 RFP 中引用 IEC 62443 要求

### 安全等级 (Security Level)

| SL | 适用场景 | 防护能力 | A4x 产品线 |
|----|----------|----------|------------|
| SL 1 | 防止偶然/无意违规 | 基本认证 + 加密 | 消费级摄像头 |
| SL 2 | 防止使用简单手段的有意攻击 | 强认证 + 加密 + 审计 | **企业级摄像头** |
| SL 3 | 防止使用复杂手段的有意攻击 | 多因素认证 + 硬件安全 | 关键基础设施 |
| SL 4 | 防止国家级攻击者 | 国防级安全 | 通常不适用 |

### SL 2 固件要求（A4x 企业级）

| 要求类别 | 具体要求 | 固件实现 |
|----------|----------|----------|
| 身份与认证 | 所有用户/设备唯一标识 + 强认证 | mTLS + 设备证书 + 用户 token |
| 使用控制 | 基于角色的访问控制 | 命令权限分级（viewer/admin） |
| 系统完整性 | 启动完整性 + 运行时检测 | Secure Boot + 固件完整性自检 |
| 数据机密性 | 传输和静态数据加密 | TLS 1.2+ / AES-GCM 存储加密 |
| 数据流限制 | 网络分段 + 防火墙规则 | 设备只连接必要端口和服务 |
| 事件响应 | 安全事件记录和上报 | 本地安全日志 + 云端事件上报 |
| 资源可用性 | 防 DoS + 容错 | 连接限速 + 看门狗 + OTA 回滚 |

### Zone & Conduit 模型

IEC 62443 将网络划分为安全区域 (Zone) 和通道 (Conduit)：

```
[外部网络 Zone]
    ↕ Conduit: HTTPS/TLS (防火墙过滤)
[A4x Cloud Zone]
    ↕ Conduit: MQTT TLS / WebRTC DTLS
[设备网络 Zone]
    └── Camera A (SL 2)
    └── Camera B (SL 2)
    ↕ Conduit: BLE (配网，临时)
[用户终端 Zone]
    └── App
```

固件关注：设备只通过定义好的 Conduit 通信，禁止开放额外端口或协议。
