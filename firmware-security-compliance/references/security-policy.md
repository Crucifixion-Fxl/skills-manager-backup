# 固件安全公司规则与方案条件

本文件承接 SKILL.md 的公司红线与默认规范；每次固件审查必须读取，并结合目标版本的适用性与证据逐项判断。规则 ID 保持不变；问题归因、存量门禁和豁免按 [SKILL.md](../SKILL.md) 执行。

局域网服务端与云端客户端分别适用通信规则，不能把设备连云要求直接套用到本地服务；详见 [通信安全](communication-security.md)。法规适用性和条款以 [合规核对清单](compliance-checklist.md) 及适用版本原文核对，公司规则不等于已取得合规结论。

## 红线（违反即不通过）

| ID | 红线规则 | 原因 |
|----|----------|------|
| RL-01 | **ECB 模式用于超过单块的数据** | ECB 泄露数据模式，对图像/视频数据尤其危险 |
| RL-02 | **MD5 或 SHA-1 用于安全目的** | 已知碰撞攻击，不可用于完整性/签名/MAC |
| RL-03 | **AES 密钥 < 128 bit** | 低于行业最低安全强度 |
| RL-04 | **TLS < 1.2 用于任何云端通信** | TLS 1.0/1.1 已被 IETF 废弃 (RFC 8996) |
| RL-05 | **OTA 固件无签名验证** | 允许攻击者刷入恶意固件 |
| RL-06 | **源码中硬编码对称密钥或通用默认密码** | 逆向/泄露即影响所有设备；EN 18031 CCK-3 强制要求 |
| RL-07 | **有 TRNG 却用 rand()/srand()** | 伪随机数可预测，密码操作必须用硬件真随机数 |
| RL-08 | **OTA 无防回滚保护** | 攻击者可降级到已知漏洞版本 |
| RL-09 | **WiFi 密码/云端 token 明文存储在 Flash** | 拆机读 Flash 即获取用户 WiFi 和云端访问权限 |
| RL-10 | **恢复出厂设置不擦除用户数据和凭证** | 二手/退货设备泄露前用户隐私 |
| RL-11 | **TLS 证书验证设置为 VERIFY_NONE** | 完全绕过证书链验证，允许中间人攻击 |
| RL-12 | **设备本地控制接口（HTTP/WS/私有 TCP）无任何认证** | 同网段或插 USB 即可下发控制、读取用户数据；magic number / 固定帧头**不是**认证 |
| RL-13 | **产测/调试接口无认证或无集中控制的开启方式** | 送样、维修、二手设备落到外部后成为完整后门；ETSI EN 303 645 §5.6 要求生产固件关闭未认证服务，EN 18031-1「访问控制/认证」要求组同样适用 |
| RL-14 | **release 固件默认开启调试通道**（ADB / 串口 shell / 调试路由 / 调试 gadget），或调试开关可被可写分区的启动钩子打开 | 违反生产默认关闭策略；是否免认证、认证后是否 root、是否能持久化，须分别核查实际认证、进程权限及启动链，不能只由端口开启推断 |
| RL-15 | **设备本地接口 `Access-Control-Allow-Origin: *`（或等效放行）** | 违反本地接口跨域白名单策略；跨站读取需核实可达性、浏览器限制、方法/预检、凭据模式和可读响应；跨站控制另查请求是否产生副作用，响应不可读不代表操作未执行。CORS、接口认证与 CSRF 分别判断 |

## 公司规范项（默认强制，不澄清）

若证据不足，处理方式 = `默认规范+建议`，在缺口中标注"需补证据（非澄清）"：

**密码算法规范**：
- mbedTLS 作为默认 TLS/密码库（除非平台有特殊需求）
- AES-128-GCM 或 AES-128-CCM 用于受限设备端加密（CCM 更省 RAM）
- AES-256-GCM 用于云端/高安全场景
- SHA-256 为最低散列算法要求
- HKDF-SHA-256 为主密钥派生函数
- nonce/IV 必须使用 TRNG 或单调递增计数器 + 设备唯一标识

**通信协议与证书规范**：
- WebSocket 必须 WSS (TLS 1.2+)，HTTP 必须 HTTPS，WebRTC 必须 DTLS-SRTP
- BLE 最低 Security Mode 1, Level 3；WiFi WPA3-SAE 优先，WPA2-TKIP 禁止
- CA Root 证书只嵌入业务需要的私有 CA，禁止全量公共 CA 包
- TLS 必须完整验证证书链（Root→Intermediate→Leaf），校验有效期+域名+用途
- 证书过期应急：支持通过 BLE 安全通道更新 CA 证书（应对仓储长期存放场景）
- 设备韧性：硬件看门狗自恢复 + 连接限速 + 异常流量检测 + 安全事件上报

**密钥管理规范**：
- 设备唯一密钥在工厂写入 eFuse（优先）或安全存储
- 每台设备唯一凭证，禁止通用默认密码，用户不可跳过认证设置
- 会话密钥通过 HKDF 从设备主密钥派生
- 密钥使用后必须安全清零 (`mbedtls_platform_zeroize`)

**OTA 与启动规范**：
- OTA 固件签名使用 ECDSA P-256 或 Ed25519
- OTA 必须组合多机制保护：签名验证 + HTTPS 安全通道 + 设备身份访问控制 (EN 18031 §6.3.2.4)
- 生产固件必须启用 Secure Boot
- 固件版本号单调递增 + 防回滚检查

**设备本地接口规范（S10）**：
- 产品基线检查按适用性执行 [配网与本地访问代码审查](device-access-review.md)，无需本次修改 BLE/Wi-Fi、ADB、产测、文件/诊断或依赖。随机值、时间窗、路径检查均不能单独证明身份认证；已有认证与认证后的操作权限分别核验
- 设备侧每个对外接口（HTTP 路由 / WS / 私有 TCP）必须有明确的鉴权判定：绑定态设备密钥派生的 token、或配对建立的会话凭据；**绑定关系快照不等于鉴权凭据**
- 监听 bind 范围最小化：只在业务需要的接口上监听（明确 bind 地址，不默认 `0.0.0.0`），并逐接口说明 WiFi STA / SoftAP / USB 三个面的可达性
- 调试与诊断路由**不进 release 构建**（编译开关默认关闭）；确需保留的必须走与产测同一套集中控制的授权流程
- 设备本地接口禁止 `Access-Control-Allow-Origin: *`；确需浏览器访问时用显式 origin allowlist
- 产测/调试通道的开启必须：设备唯一密钥参与的 challenge-response（禁止固定口令/固定帧头）+ 时间窗 + 开启事件审计上报；**开启能力集中控制，不下发到单台设备的静态配置**
- release 固件默认关闭 ADB / 串口 shell / 调试 USB gadget；开启需签名令牌或产测夹具物理条件
- 可写分区（如 `/userdata`）中的启动钩子、`LD_PRELOAD`、配置覆盖在 release 必须禁用或强制签名校验——否则一次文件写入即等于 root 持久化

**本地存储安全规范**：
- WiFi 密码、云端 token 等凭证必须加密存储（AES-GCM + 设备密钥派生的存储密钥）
- SD 卡视频录像必须加密（AES-128-CTR，密钥由设备密钥 + 用户绑定信息派生）
- 本地日志禁止包含明文凭证、用户 PII、完整网络请求
- 恢复出厂设置必须擦除：WiFi 凭证、云端 token、用户配置、SD 卡加密密钥
- 生产固件必须禁用调试端口（UART/JTAG），或通过认证机制保护
- 数据最小化：固件不采集非功能必需的用户数据；支持用户删除个人数据

## 方案条件

缺失信息只暂缓依赖该信息的决策，继续独立的源码、认证和数据流检查：

| 所需信息 | 影响域 | 影响的方案决策 |
|---------|--------|----------|
| SOC 平台与密码硬件能力 | S1-S4 | 直接决定算法和模式选择 |
| 安全存储类型（eFuse/SE/TEE/无） | S4 | 决定密钥保护方案 |
| 视频流是否经过公网 | S7 | 决定是否需要 E2E 加密 |
| 是否需要 FIPS 140-2/3 认证 | S1-S4 | 影响密码库选择（wolfSSL FIPS） |
| 是否需要 Matter 协议认证 | S3, S9 | Matter 强制 AES-128-CCM + 特定证书体系 |
| 设备是否支持 SD 卡录像 | S8 | 决定是否需要本地视频加密方案 |
| 设备是否有调试端口暴露 | S8/S10 | 决定调试接口保护方案 |
| 设备形态（云端客户端 / 局域网服务端 / 混合） | S3/S10 | 决定走哪一套通信与鉴权规则 |
| 设备是否对外监听端口、监听在哪些网络接口 | S10 | 决定鉴权与 bind 收敛范围 |
| 产测/调试通道的开启方式与控制方 | S10 | 决定是否满足"集中控制" |
| 设备预期仓储周期 | S3 | 长期存放可能导致证书过期，影响证书更新策略 |
| 产品是否销售到 EU 市场 | S9 | 决定 EN 18031 是否适用（2025-08-01 起 EU 强制） |
| 产品是否涉及设备端支付/金融功能 | S9 | 决定 EN 18031-3（反欺诈）是否适用 |

自动审查优先读取当前环境允许的 `docs/security/device-profile.yml`，其次为 `AGENTS.md` / `CLAUDE.md` / 构建配置。建议 profile 字段：`soc`、`crypto_hw`、`secure_storage`、`ram_mb`、`tls_lib`、`device_form`（A=云端客户端、B=局域网服务端、C=混合）、`sd_recording`、`debug_ports`、`markets`、`needs_fips`、`needs_matter`、`storage_period_months`。约定文件缺失不能作为安全功能缺失的证据。

算法和硬件选型详见 [密码算法指南](crypto-algorithm-guide.md)。HMAC-SHA-256 的公司默认密钥长度为至少 256 bit；密码登录入口另查哈希、锁定、默认值、每机配置和尝试限制，ADB 主机认证单列。硬件密钥存储依目标芯片实际读写保护判断，不由 eFuse/SE/TEE 名称推断不可导出；无安全存储时应说明替代保护的根密钥来源、残余风险与迁移条件。
