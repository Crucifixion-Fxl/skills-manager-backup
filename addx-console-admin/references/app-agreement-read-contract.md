# App agreement metadata read contract

Use the native Token read adapters for the server-side App agreement configuration list and a tenant already returned by that authenticated enterprise selection. Tenant codes and enterprise customer codes must come from actual metadata; do not guess IDs or use device CUIDs.

The policy adapter accepts no caller-supplied host. It resolves the unique selected tenant from a fresh enterprise-scoped tenant response and uses its first configured host, matching the webpage default. Approved source-derived DNS suffixes are `addx.live`, `a4x.io`, `theunismart.com`, and `vicohome.io`. The latter was added after an authenticated actual tenant configuration and its matching webpage policy request established that product domain. This is a bounded scope correction, not permission to request arbitrary URLs. Suffix matching requires a full hostname or a dot boundary; lookalike, path, port, userinfo, IP, noncanonical whitespace/case, absent host and enterprise/tenant mismatch fail before the policy request.

Before navigating a tenant detail page, confirm its actual first configured host. The backend performs a GET to `https://api.<configured-host>/actuator/health`; report this read network side effect. The legacy helper has no explicit timeout or redirect restriction, so source review does not establish runtime redirect behavior. A supplied valid host avoids the no-host S3 presigned URL fallback. Never invent a host or call that fallback to produce an apparent PASS.

Only whitelisted enterprise, tenant, template-name, language-count and timestamp metadata may be returned. Drop legal HTML, template definitions/values, policy IDs, host URLs, derived links and credentials. Template placeholder objects are created only in memory and are not evidence of saved or published policies. Read-only view comparisons should use card title, language count and displayed update time; do not click link retrieval, preview, edit or publish. Offline contract tests and webpage-only success do not replace native acceptance on both hosts.
