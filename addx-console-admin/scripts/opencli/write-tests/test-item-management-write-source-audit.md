# Test-item management action/source audit (offline only)

No production/browser/credential access or business writes were performed. This report is source and fixture evidence only, not real write acceptance and not a registered command.

Detail and edit pages auto-load `/test/item/manage/info`. Missing saved configuration causes a manager INSERT plus default manufacturer initialization. Editing/reusing loads the target and potentially the source as well. Treat these page openings as mixed operations; prior list existence cannot eliminate races. Unconfigured candidate lists describe potential targets, not saved state.

Draft save is an upsert that resets parent status to NO_RELEASE (1). Nonempty factory input replaces each included art/factory item list by delete/reinsert, then deletes omitted stored pairs and their items. Empty factory input returns without clearing children, although parent status/time may already change. The separate manufacturer/save contract uses relation input for insertion and manufacturerIds for deletion, and does not explicitly clean item children. No transaction annotation applies to the inspected manager/child save methods; rollback and FK cascades remain unproven. There is no expected-version/CAS predicate, and fields inherited by request DTO are not a whitelist of safe mutable fields.

`info` is also a lossy and dynamic saved-state projection: missing catalogue items/parameters are skipped, art mismatches filtered, raw expand emptied. Aging parameters resolve current published script content from S3 and include presigned URLs, rather than preserving original raw saved configuration. Reports must avoid script contents, threshold values and URLs. No audited authoritative raw/full child snapshot endpoint is available to make a safe roundtrip replacement.

Submit-task changes rows to status 3 and inserts a PROD release task. Save-and-submit runs two writes in sequence; later failure can leave the saved draft. Batchsave saves targets, invokes generic release and may immediately create Git release/PR artifacts. The current release page uses /device/release APIs; cancellation may delete a Git branch and update task and management status. Cancellation is not manager deletion. Legacy /test/item/manage/release and release-task declarations have no active matching handlers in the inspected manager controller; do not invent a manager delete command.

The unregistered pure audit helper requires dry-run and rejects unknown fields/proof flags. Eight offline tests cover candidate/saved distinction, detail hidden initialization, duplicate/missing targets, known source status/model-type enums, lossy state refusal, release workflow and absent delete. It produces no network operation, credential access, payload or executable readiness. Even a saved-list row is insufficient for save execution.

Required before any future writer: noninitializing authoritative target existence/absence, full raw art/factory/item/param snapshots including orphaned rows, strict mutable field/schema constraints, complete intended replacement with explicit deletions, published catalogue and required parameter validation, caller/deployment write authorization, expected version or server CAS, transaction/rollback boundary and release-workflow scope/status/readback. These remain uncovered.

Generic method suggestion: audit UI autoload as well as button calls; catalogue-filtered/dynamically hydrated detail is not raw saved state; distinguish candidate, create-on-read, upsert, empty no-op and replacement; trace batch helpers through release/Git calls; never equate task deletion with resource deletion; source-confirmed mutation or unproven full state should remain a pure intent audit without payload/submit.
