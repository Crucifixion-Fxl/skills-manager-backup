# Production binding save readiness audit

This pure source/fixture audit does not register an OpenCLI command, issue HTTP, create a save payload, or enable submission. `assessBindingSaveIntent` accepts only dry-run `template`/`assess`; selectors are exact modelNo/artPlanId/distinct artIds. Its result always refuses to certify complete persisted state. Boolean flags, ordinary proof strings, additional context and release controls are rejected.

`get(modelNo)` collects arts across every model-plan relation; it does not accept a plan ID. For each art it queries all model_art_component rows by model+art, then builds the current catalog/group view. Empty orders cause default groups; only currently known component definitions render, unmatched rows disappear, component duplicates collapse to first match, group metadata comes from first record, BOX_PACK product duplicates collapse to the smallest row ID. Full raw IDs/artPlanId/publishStatus/versions are not exposed as a recoverable snapshot. List status/count comes from published selected rows and is not full saved-state proof. Bounded list observations do not prove a unique model-plan association.

Save request fields are modelNo/artConfigs/saveAndRelease(defaultfalse); artPlanId is absent. Per **included art**, save deletes every old row by modelNo+artId without plan filtering, then inserts model-level/group/component rows. Omitted arts are retained, but missing groups or unselected components inside a changed art disappear. Array order is re-numbered 0..N-1 rather than preserving supplied group order. New row IDs are allocated and null counts become0. Plain draft save writes publishStatus1, replacing old published2 rows; it can alter availability/behavior even without the publish flag. Runtime readers' exact interpretation is not certified here.

BOX_PACK uses group row componentId0, product-code row componentId-1, and selected child scope rows >0. Product config fields are conditionally validated; invalid config can throw after old rows were already deleted/earlier rows inserted. Group barCodeType encodes tail-box allowance, distinct from productBarCodeType. These cannot be flattened into ordinary child component rows or dropped because the UI hides them.

Save resolves artPlanId by lowest model planDetailId if multiple matches, but status update later selectOne(model) can fail on multiple rows or missing relation. It recomputes publication-derived model status and writes operation log. No explicit transaction annotation appears on this service/class/save in the reviewed source; external transaction aspects, DB triggers and rollback policy remain unknown. No version/CAS expected-current check exists. The 0configured/0total status calculation and list presentation need not agree, so a status label cannot authorize mutation.

Required before any executable candidate: authoritative complete raw saved rows for affected model+arts across plans, full plan association set, hidden sentinel/publication/value preservation, exact deletion/diff scope, version/atomic replacement guarantee, draft/publication effect policy, deployed contract and effective action permission. Never turn `/get` defaults into a save body or certify state from a normal evidence string. This audit's intentHash binds selectors and observed metadata only; it is not a deletion-scope authorization or executable plan hash.
