# Production art/process write audit (offline only)

No live SaaS, browser, credential, business write, deployment or publication was used. Eight fixture tests pass. This is an unregistered pure readiness audit, not an executable write command or real write acceptance.

The art upsert handler defaults publish=true. Draft explicitly sets publishStatus=0; create checks duplicate name, edit uses updateById with no target existence/CAS or lifecycle gate. The service has DSTransactional, but publication touches factory runtime records through async code. Effective transaction interception and cross-thread/all-factory atomicity are unproven. A timestamp assignment is not a caller version predicate.

Raw ext is shared JSON. Save reads existing ext and overlays only nonnull code and inProduceCodeRuleId; when the merged map is nonempty it replaces request.ext, so submitted arbitrary ext is not a supported full replacement. If extMap stays empty, raw request.ext may instead survive. Malformed stored ext parses to null, potentially losing unknown keys when an overlay is then written. Null/omitted rule does not clear a stored rule. Manual generate type5 only checks nonnull rule, without proving rule existence, positivity or applicable scope. A safer offline intent must refuse malformed ext/raw JSON writes and preserve unknown keys, while keeping missing catalogue/scope checks explicit.

The query/all art methods directly select rows and convert ext without initialization in the inspected service; raw ext remains alongside derived fields. Malformed ext can fail conversion. UI edit/detail take a route.query snapshot from list fields, rather than reloading the exact raw row. Editor autoload queries abilities and code-rule selections; those downstream selection implementations were not audited here. The editor omits raw ext/display types and sends manual rule only when selected, so changing type does not clear an old stored rule.

Publish by art selects default plans first. With no matching default plans it returns after marking published, before considering model-plan overrides. Otherwise it unions affected factories and recalculates every factory plan/override, disabling old runtime art records and updating/inserting new ones. Publication scope therefore exceeds one art; lifecycle and current source/runtime consistency are not established. No art delete or process catalogue CRUD contract is exposed by the reviewed controller/API. Do not invent one.

The pure helper checks exact target in an unfiltered fixture snapshot, known enum values, valid object-shaped raw ext, safe integer patch values and a positive manual rule. It summarizes preserved/changed ext key counts and hashes snapshot drift, without raw ext output. The digest is neither authorization nor CAS. Template/create/edit/publish/delete all remain nonexecutable, with no payload or transport; unknown fields, publish switches, raw ext and submit are rejected.

Uncovered before any future writer: complete mutable field and raw ext schema, unique code/name and caller scope contracts, fresh target existence and immutable fields, current rule catalogue/permission and cross-repository generation semantics, affected plan/manual-art ordering, full factory runtime state, transaction/rollback/CAS/readback, deployed lifecycle/write grants, and delete/process CRUD contracts. Editor option endpoint side effects remain unaudited.

Generic method suggestion: compare route snapshots with raw saved rows; audit shared JSON merge and null-clearing behavior rather than treating ext as replaceable; distinguish transactional annotations from effective cross-thread atomicity; trace publish even when no default resource exists; preserve unknown keys and reject malformed state; keep source-only mutation intents nonexecutable when authority, full runtime scope or CAS remains unproven.
