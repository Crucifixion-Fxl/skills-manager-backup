# App agreement template/customer-policy write source audit

OFFLINE_VERIFIED_ONLY / NOT_LIVE_ACCEPTED. No browser, credentials, real SaaS/business requests, S3 or production writes were used. This does not repeat the other agent's template/publication-statistics read work. It maps write and hidden-write effects only.

Policy save cannot be made draft-only by publish=false: the service ignores that parameter and publishes whenever the selected template is published. The single-policy path templateId is not used to bind the body. Existing policy IDs are updated without proving original caller/tenant/template ownership. Default language changes reset other rows using submitted templateName, while the shared default object can be overwritten. No CAS or authoritative uniqueness proof exists in the inspected code.

Publish async work may create S3 buckets and writes localized/default HTML in every configured environment. Cancel/delete resolves all configured tenant hostnames and deletes localized/default objects across every environment, exceeding one saved policy host. Hostname dot/hyphen normalization can collide. Errors are swallowed inside async methods and by future waits; a true API result or generated URL does not prove object publication or deletion. SQL Transactional does not make external S3 changes rollback atomically; async reads of a just-inserted row across transaction boundaries are also unproven.

Template save can rename every language sharing a submitted code before saving the target. Edit resets publishStatus0 and nulls code/name/language fields, but has no target existence/version/ownership checks. Controller batch save loops separate service transactions. Template name enable/disable/publish/delete targets all matching language rows and related customer policies. Delete scopes caller only at a later policy SQL delete, after unscoped template selection/S3 cancellation/template deletion. Single policy delete has a route policyId versus PathVariable templateId mismatch; do not assume an executable endpoint.

The template editor's real language change calls handleResquest(true) and batch upsert, automatically saving the previous language. Initial loading uses the no-real-change flag and skips that write. A language tab in an editor is not a read-only action.

Policy cards are not authoritative full saved state: only active template/policy status rows, host filtering, findAny duplicate collapse and unsaved placeholders are returned. They exclude disabled rows, duplicates, other hosts/tenants and complete S3 state. Health GET chooses domain prefix without independently proving transport status. Readback must separately verify database state, default-language relationships and authorized exact external object scope, without publishing bodies, fields or signed links.

The pure unregistered helper refuses submit, publish flags, body/proof fields and mismatched ID/template/tenant/host fixtures. It distinguishes unsaved placeholders from existing policy IDs and flags published-template draft save, group blast scope and broken delete binding. Eight offline tests pass; no payload or HTTP is implemented, and no observed state grants execution.

Uncovered: authoritative raw full policy/template relationship state, all customer/tenant/host/environment object scope, caller/deployment permissions, mutable-field/required-HTML schema, uniqueness/default-language constraints, CAS/transaction/async visibility, exact object version/atomic rollback/readback, route fix for policy delete and live writes. All real business writes remain zero.

Generic method suggestion: trace actual use of publish flags rather than trusting their names; follow async storage effects across all environments/hosts and account for swallowed errors; audit editors' tab/locale changes for autosave; distinguish cards/placeholders from raw saved relationships; bind path/body identifiers to authoritative ownership; require separate SQL and object-store readback and keep unsafe source-only plans nonexecutable.
