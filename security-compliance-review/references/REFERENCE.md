## Review 对象与证据形态

本次 review 的对象可能是**文档**或**代码/配置**（或两者）。对每个关键控制点，必须明确"证据来自哪里"：

- **代码/配置证据**：实现、默认配置、权限校验、加密/脱敏/审计的落点
- **文档证据**：策略/设计/流程（例如：数据分类口径、访问边界、审计与保留、例外流程、第三方边界）

## 系统类型判定

必须先判断变更属于哪种系统类型，**若无法判定，必须先输出"澄清问题"，在拿到答案前不进入后续检查与结论**：

| 系统类型 | 说明 | 检查重点 |
|----------|------|----------|
| **C 端系统** | 面向终端用户；对外 API/客户端可直接触达；第三方/渠道触达用户 | 对外暴露面、第三方边界、用户可触达能力、日志/埋点泄露、凭证与高敏数据处理 |
| **对内产品** | 面向员工/内部用户；内部工具/后台/运营系统 | 平台化要求（脱敏+审计）、权限与导出控制、生产数据旁路（直连 DB/K8s/VPC、debug/exec、脚本）与审计证据 |
| **混合** | 同时包含对外用户链路与对内运营/后台链路 | 分别按两套策略独立检查与下结论，并在总结合并 |

**若系统类型未知，必须先澄清（阻断结论）：**

- [ ] 该变更影响的用户是谁（终端用户/员工/两者）？
- [ ] 是否新增/修改对外 API、SDK、客户端字段展示或第三方可见字段？
- [ ] 是否新增/修改内部后台能力（查询、导出、批量、调试、脚本）？

| 风险ID | 风险类别 | 说明 | 自动识别线索示例 |
|--------|----------|------|------------------|
| R0 | 系统类型 | C 端 vs 对内（决定必选控制） | - |
| R1 | 数据分类 | 个人数据/可关联数据/高敏内容（视频/地址电话） | 表结构、字段命名、API 响应 |
| R2 | 跨界访问 | 跨域/跨实体/跨地域；是否可能让非授权人员接触敏感数据 | 权限角色变更、跨域调用 |
| R3 | 访问绕过 | 直连 DB/K8s/VPC、debug/exec、脚本旁路受限平台 | 数据库连接字符串、kubectl 命令、SSH 配置 |
| R4 | 批量能力 | 导出/批量查询/枚举式规则圈人/跨工单聚合/批量触达 | `export`/`download`/`csv`/`xlsx`/`report`/`bulk`/`batch` |
| R5 | 观测泄露 | 日志/埋点/错误事件是否携带 PII、请求体、设备标识、IP 等 | logger 调用、埋点 SDK、错误上报 |
| R6 | Secrets/凭证 | 密码/token/key 是否可能以明文出现在存储/传输/日志/错误上报 | 硬编码字符串、环境变量、配置文件 |
| R7 | 第三方边界 | 第三方可见数据、管理员权限、审计能力是否变化 | 第三方 SDK、Webhook、外部 API 调用、vendor endpoint |
| R8 | 脱敏与审计平台 | 对内产品是否必须接入脱敏平台+审计平台 | 数据访问接口、查询 API |
| R9 | 跨实体/跨境访问 | US Entity vs CN Entity 的访问边界是否被削弱 | 权限配置、数据回传、break-glass 流程 |
| R10 | 批量敏感数据风险 | 是否新增/放宽批量查询、导出、跨工单聚合、日志批量拉取能力 | 分页遍历、全量拉取、后台任务导出、BI 报表 |
| R11 | 高敏数据零人工访问 | 视频/地址/电话等是否可能被员工直接查看或导出 | 视频播放接口、地址展示字段 |
| R12 | 保留与删除/DSAR | 保留周期与删除链路是否变化；是否影响数据主体权利闭环 | TTL/retention config、清理 job、删除 API |
| R13 | 合规框架推断 | 基于用户/区域、系统类型、数据字段、业务场景推断可能相关的法规/标准 | 用户地理位置、数据类型 |
| R14 | Agent Skills 供应链 | 项目中的 AI Agent Skills 是否存在 Prompt 注入、凭证泄露、脚本风险 | `SKILL.md`、`.cursor/skills/`、`.cursor/rules/`、`AGENTS.md` |

## 公司规范项详细说明

以下为公司研发规范，**默认强制执行**；若输入/证据未覆盖，不需要向用户澄清细节，直接给出"按公司规范落地"的整改建议，并在缺口里标记为"需补证据（非澄清）"。

### R5 观测泄露

| 要求 | 说明 |
|------|------|
| 统一 Observability SDK | 必须使用公司统一的埋点/日志 SDK |
| 日志字段白名单/黑名单 | SDK 层实现字段拦截与脱敏 |
| 脱敏策略 | 敏感字段源头脱敏 |
| 导出限制 | 日志导出需审计与限制 |
| 禁止绕过 | 禁止自建上报链路 |

### R6 Secrets/凭证

| 要求 | 说明 |
|------|------|
| Secret Zero | 应用启动时从安全源获取 secrets |
| 禁止明文 secret | 代码/配置中不得出现明文 secret |
| 禁止硬编码 token/key | 不得硬编码任何认证凭证 |
| 轮换与审计 | secrets 定期轮换，访问可审计 |

### CI/CD 与 Helm/IaC

| 要求 | 说明 |
|------|------|
| GitLab CI | 使用 Vault 注入 secrets |
| Helm values/chart | 必须走 Vault 注入与受控 Secret 引用 |
| K8s manifests | 禁止明文 secret，使用 External Secrets 或 Vault |

### 日志/错误上报

| 要求 | 说明 |
|------|------|
| 源头脱敏 | 敏感字段在源头脱敏后再上报 |
| 导出限制 | 错误日志导出需审计 |
| 不含密码/token | 日志/错误上报中不得出现密码或 token |

### R14 Agent Skills 供应链

> 仅当 MR/仓库中检测到 Agent Skills 相关文件时触发；否则标 `不相关(N/A)`。

**自动识别线索**：
- `SKILL.md` 文件（Agent Skills 规范）
- `.cursor/skills/` 目录（Cursor 项目级 Skills）
- `.cursor/rules/` 目录（Cursor Rules）
- `AGENTS.md` 文件（Codex 格式）
- `agents.json` 或 `agents.yaml`

| 要求 | 说明 |
|------|------|
| 禁止未审核的第三方 Skills | 只允许使用经内部审核的 Skills（来源：`engineering/skills` 仓库） |
| Prompt 注入检测 | 检查是否包含 `ignore previous instructions`、`bypass safety`、`override system` 等注入模式 |
| 硬编码凭证检测 | 检查是否包含真实 API Key（`sk-`/`AKIA`/`ghp_`/`glpat-`）、密码、连接字符串 |
| 无脚本策略 | 含脚本的 Skills 漏洞风险是纯指令 Skills 的 2.12 倍（[arXiv 2510.26328](https://arxiv.org/abs/2510.26328)），优先使用纯指令 Skills |
| HTML 隐藏内容检测 | 检查 `<!-- -->` 注释（对人不可见但 LLM 可读取，常见攻击载体） |
| 内部信息保护 | Skills 中不应包含内部域名、IP 地址、系统架构等敏感信息 |
| 文件大小合规 | SKILL.md 建议 ≤ 500 行，过长文件增加 Prompt 注入隐藏风险 |

**风险背景**（基于 31,132 个 Skills 的学术研究）：
- **26.1%** 的 Skills 包含至少一个漏洞
- **13.3%** 存在数据泄露风险
- **11.8%** 可实现权限提升
- 每一行 Skill 文件都作为 LLM 指令执行，Prompt 注入极其简单

## 必须澄清项详细说明

以下项目会**实质影响风险判断与结论**，缺失时必须进入澄清/阻断逻辑。

### 系统类型（未知则阻断）

必须明确是 C 端系统 / 对内产品 / 混合，否则阻断后续检查。

### 导出/批量能力（先自动判断，无法判断再澄清）

优先从代码/配置/文档自动识别是否涉及导出/批量查询/跨工单聚合/批量触达；若无法判断或存在迹象但控制未说明，则需要澄清，**通常为阻断项**。

**自动识别线索**：
- `export`/`download`/`csv`/`xlsx`/`report`/`bulk`/`batch` 相关接口或 UI
- 分页遍历/全量拉取
- 后台任务导出
- 管理员工具
- BI 报表下载
- 日志批量拉取脚本

### 第三方边界（先自动判断，无法判断再澄清）

优先从依赖与集成配置自动识别是否新增/修改第三方（SaaS/渠道/供应商）数据可见性与导出能力；若无法判断或存在迹象但边界/审计未说明，则需要澄清，**通常为阻断项**。

**自动识别线索**：
- 新增/修改第三方 SDK
- Webhook
- 外部 API 调用
- Helm values/环境变量中的 vendor endpoint
- 权限角色与导出开关
- 第三方可见字段映射

### 加密与密钥管理方案（先自动判断，无法判断再澄清）

若本次变更涉及 PIN/密码/OTP/token/key 等认证要素或敏感字段处理，必须确认其生成/存储/传输/加密与密钥轮换；优先从实现与配置自动识别，**无法判断则澄清并按高风险阻断**。

**自动识别线索**：
- 密码学库使用
- KMS/Vault 集成
- DB 字段加密/哈希与盐
- 密钥引用方式（env/secret/vault）
- CI/Helm 注入方式

### 新增 PII 字段与脱敏方案

若出现 `user_id/SN/email` 之外的 PII 字段，必须澄清其脱敏策略、落点（统一 SDK/平台/服务侧）、导出限制与审计证据（**未知通常阻断**）。

### 跨实体/跨境与例外路径（先自动判断，无法判断再澄清）

仅当本次变更触达"生产数据访问边界/权限模型/受限平台/例外流程/跨实体数据流"时才相关；优先从代码/配置/流程文档自动判断，无法判断或疑似影响边界但缺少证据时需要澄清（**高风险时阻断**）。

**自动识别线索**：
- 权限角色变更
- 后台查询/导出能力
- 受限平台接入/绕过
- 跨域调用
- 数据回传到非授权侧
- break-glass/审批流改动

### 保留与删除/DSAR 变化（先自动判断，无法判断再澄清）

仅当本次变更新增/变更个人数据存储、日志/审计保留、删除/归档链路、或 DSAR（访问/更正/删除/导出）流程时才相关；否则标 `不相关(N/A)`。

**自动识别线索**：
- 新增表/字段/对象存储
- TTL/retention config
- 清理 job
- 备份/归档策略
- 删除 API/worker
- DSAR 工单/流程集成

## 红线规则详细说明

以下为**绝对红线**，违反必须判定 `需整改/不通过`：

### 视频数据零人工访问

- **规则**：无论系统类型与操作者是谁，**任何员工（含运维/支持）均禁止直接访问原始视频**
- **验证**：在代码/配置或文档中确认"无人工访问路径 + 受控服务间访问 + 审计证据"
- **违反**：若发现存在可人工访问/导出视频的路径，必须判定 `需整改/不通过`

### 密码/凭证红线

- **规则**：不存储/不传输明文密码；日志/错误上报不出现密码或 token
- **验证**：检查存储层加密/哈希、传输层加密、日志输出
- **违反**：发现明文密码存储/传输/日志输出，必须判定 `需整改/不通过`

### 高敏数据（地址/电话）零人工访问

- **规则**：地址/电话等高敏字段零人工访问，仅服务间受控调用
- **验证**：确认无人工查看入口、服务间调用有审计
- **违反**：发现人工可查看/导出入口，必须判定 `需整改/不通过`

## 敏感线索触发的阻断澄清

如果输入材料出现下列线索之一，但未明确说明保护策略/证据，必须将其列为**阻断项**并优先追问：

| 线索类型 | 示例 |
|----------|------|
| **认证要素/秘密** | PIN code、验证码、口令、密保答案、重置 token、session、API token、Private Key |
| **高敏个人数据/受监管数据** | 地址/电话、精确定位、音频、医疗/健康信息（PHI）、金融账号 |
| **加密缺口** | 未说明传输加密、存储加密、密钥管理（KMS/Vault）、加密算法与轮换、不可逆哈希/盐 |
| **观测数据偏离公司规范** | 非统一埋点/日志 SDK、自建上报链路、上报内容疑似包含敏感字段且缺少拦截/脱敏 |
| **运维/支持访问边界偏离公司规范** | 可绕过受限平台直连、可查看明文敏感字段、可导出/批量拉取、缺少工单绑定与全量审计 |

## 合规框架自动推断

不要求用户提供合规/认证目标。必须基于以下信息自动推断可能相关的法规/标准，并在输出中明确标注为"**推断/假设**"：

| 推断依据 | 可能相关的法规/标准 |
|----------|---------------------|
| 用户位于欧洲 | GDPR |
| 用户位于美国加州 | CCPA/CPRA |
| 涉及健康/医疗数据 | HIPAA |
| 企业级 SaaS | SOC2 Type II |
| 涉及个人数据处理 | ISO 27701 |

**注意**：推断仅用于指导检查优先级与整改建议，不作为既定事实或对外承诺。

## 控制点库

### 通用控制点

| 控制点 | 要求 |
|--------|------|
| 受限平台访问 | 禁止直连与绕过；所有数据访问/操作经受限平台与审计 |
| 脱敏策略 | email alias / temporary id / 新增 PII 的脱敏策略评审 |
| 审计证据 | 操作可追溯主体+原因+时间窗+工单/活动 |
| 导出/批量能力 | 默认强限制（阈值/频控/审批/审计/告警/冻结） |
| 第三方边界 | 第三方可见字段最小化；权限与审计；导出限制；变更需证据 |
| 跨实体/跨境边界 | US/CN 边界明确；例外路径由授权侧执行并回传脱敏结论 |
| 批量风险控制 | 针对批量查询/导出/聚合有阈值、频控、告警、冻结与审计证据 |
| 保留与删除 | 保留周期明确；删除覆盖备份/归档；可提供执行证据 |

### C 端系统专属控制点

| 控制点 | 要求 |
|--------|------|
| 对外接口最小化 | API/客户端不暴露不必要敏感字段或可关联标识符 |
| 用户触达边界 | 第三方/渠道只能通过平台规则触达，拿不到用户直接标识符 |
| 视频（红线） | 员工不可直接访问原始视频；仅服务间受控处理与审计 |
| 紧急服务数据 | 地址/电话零人工访问，仅服务间受控调用并审计 |
| 假名化与映射表治理 | temporary id / email alias 映射表隔离、最小权限、默认禁导出、全量审计、过期语义 |
| DSAR 影响 | 是否影响用户访问/更正/删除/导出闭环 |

### 对内产品专属控制点

| 控制点 | 要求 |
|--------|------|
| 强制平台化 | 接入脱敏+审计平台；不得直连生产敏感数据源；前端不得展示明文敏感字段 |
| 权限与导出 | 最小权限；导出/批量默认强限制并全量审计；管理员能力不得形成旁路 |
| 实体边界与例外路径 | 例外查询由授权实体执行并仅回传脱敏结论 |
| 高敏数据零人工访问 | 视频/地址/电话等高敏字段内部系统默认不可见；仅服务间受控调用并全量审计 |

### ❌ Bad - 违规示例

#### 1. 明文 Secret 硬编码

```python
# 问题：硬编码 API key（违反 R6）
API_KEY = "sk-1234567890abcdef"

def call_api():
    requests.get(url, headers={"Authorization": f"Bearer {API_KEY}"})
```

**问题分析**：
- 违反 Secret Zero 原则
- 凭证可能泄露到版本控制
- 无法轮换和审计

#### 2. 日志包含敏感信息

```java
// 问题：日志输出用户密码（违反 R5、R6 红线）
logger.info("User login: username={}, password={}", username, password);
```

**问题分析**：
- 密码出现在日志中，违反红线规则
- 日志可能被导出或被多人访问

#### 3. SQL 直连绕过审计

```python
# 问题：直连生产数据库，绕过审计平台（违反 R3、R8）
conn = psycopg2.connect("postgresql://prod-db:5432/users")
cursor.execute("SELECT * FROM users WHERE email = %s", (email,))
```

**问题分析**：
- 绕过受限平台直连生产数据库
- 无脱敏、无审计
- 对内产品未平台化

#### 4. 批量导出无控制

```python
# 问题：批量导出用户数据无限制（违反 R4、R10）
@app.route('/admin/export/users')
```

**问题分析**：

- 无审批流程
- 无审计日志

#### 5. 第三方可见敏感字段

```javascript

  address: user.address
```

- 符合公司研发规范

#### 4. 批量导出有控制

```python
# 正确：批量导出有完整控制
@app.route('/admin/export/users')
@require_permission('export:users')
@rate_limit(max_per_day=10)
@audit_log('user_export')
def export_users():
    if request.args.get('count', 0) > 1000:
```

**合规点**：

- 频率限制

- 数量阈值
- 审批流程
- 字段脱敏
