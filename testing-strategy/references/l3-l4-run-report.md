# L3/L4 运行报告：测试环境与真实性保证

何时读：要给 L3 或 L4 出 Playwright 式运行报告，或者有人问「测试环境是什么样的」「怎么证明结果是真的」时。页面外观、脱敏红线和呈现面仍以 SKILL.md Step 4.7 为准，本文件只补两块：**测试环境**和**真实性保证**，以及支撑它们的数据从哪来。

报告必含（逐项对照）：

1. L3 与 L4 用**同一个渲染器**，页面自包含、无外部资源、无 `<script>`（状态筛选用纯 CSS，如 radio + `:has()`）。
2. 原始记录 JSON 由运行时插件写出，随报告保存；页脚列 sha256 与重新生成命令。
3. 每条用例：步骤树（每步耗时、请求数）、transport 层网络请求表、附件、失败原文。
4. 「测试环境」块：逐组件字段见第 3 节，含替身清单。
5. 「真实性保证」块：检查 A–I 由记录计算，任一 ✗ 整份不通过；其中 A 要求 L4 常驻服务从固定到被测提交的 worktree 启动，报告脚本运行前校验服务 commit，不一致拒跑。
6. 防假绿改动表：在临时 worktree 里先跑基线，再逐处改坏、跑守护用例、`git checkout` 还原；表里列每处改动的 diff、守护用例、改动后结果、抓住/漏过。
7. L4 另含数据卫生声明（第 6 节）以及 Step 4.7 的 L4 附加块。

目录：1 数据流 · 2 用例块 · 3 测试环境块 · 4 真实性保证块 · 5 防假绿改动 · 6 L4 数据卫生 · 7 反模式 · 8 参考实现

## 1. 数据流：记录 → 渲染，不手写

```
测试运行 ──(记录插件/reporter)──> 原始记录 JSON（每个套件一份，另有 mutations.json）
                                        │  不编辑，随报告一起保存（L4 进仓；L3 作为 pipeline artifact）
                                        ▼
                                    渲染器 ──> 自包含 HTML
```

- L3 与 L4 用**同一个渲染器**。环境、步骤、网络、结论全部来自运行时记录，报告里不出现人手写的「已验证」。
- 页脚列出每份原始记录的 sha256 和重新生成命令；同一组记录重新渲染必须得到相同页面（Step 4.7 的确定性要求）。
- 记录插件在 transport 层记录网络往返（例如 Python `http.client`、Go `http.RoundTripper`、Playwright 自带 trace），不依赖被测代码自己打日志。

## 2. 用例块

每条用例可折叠，展开后依次是：

| 块 | 内容 |
|---|---|
| 头部 | 用例编号（`L{层级}-<MODULE>-NNN`）、标题、文件:行、结果、耗时、各阶段（setup/call/teardown）耗时 |
| 步骤树 | 与 Playwright `test.step` 等价：每步标题、耗时、该步发出的请求数，可嵌套；失败步骤标红并挂错误原文 |
| 核对步骤 | 标题以「核对：」开头并写明通道，例如「核对：直接列对象存储前缀（绕开 gateway）」「核对：官方客户端查询 hub」 |
| 网络请求表 | 方法、目标 `host:port`、路径（去掉查询串）、状态码、耗时、响应字节 |
| 附件 | 捕获的输出、观测值（如对象数、查询读回的值、回执 ID） |
| 失败原文 | 断言与 traceback，脱敏后原样 |

## 3. 测试环境块（逐组件，必填）

每个组件一行，字段缺一不可；由夹具或启动脚本在运行时写进记录，不由人填。

| 字段 | 说明 | 例 |
|---|---|---|
| 组件 | 被测服务、依赖、客户端 | gateway、hub、对象存储、编排器、SDK wheel、CLI |
| 真实 / 替身 | 替身要写替了什么、为什么 | Trackman 拉取：夹具报告（第三方，不可控） |
| 谁启动 | 测试夹具临时起（L3） / 操作者常驻（L4） | `scripts/<x>-lan.sh up`，固定提交的 worktree |
| 地址 | 实际监听或访问的 URL | `http://192.168.20.24:8070` |
| PID | 被测进程号 | 2548932 |
| 版本或 commit | 服务的 git SHA、依赖版本 | hub `6c632ec`、rerun-sdk 0.38.1 |
| 数据存储 | 临时（每用例 / 每模块）还是持久；与谁共享 | 临时 sqlite；共享 MinIO，每用例独立前缀 |
| 客户端制品 | wheel、CLI、App 包的 sha256 | `addx_collect_sdk-*.whl` sha256 |
| 网络范围 | 回环 / 局域网 / staging | L4 只允许环境地址 |

L3 与 L4 的差别必须在这张表里一眼可见：L3 的服务由夹具在临时端口起、数据临时；L4 打的是操作者已经启动的常驻服务，测试进程不起服务。

## 4. 真实性保证块（逐条计算）

每条是一个由原始记录**计算**出来的检查，显示 ✓/✗ 和证据；任何一条 ✗，整份报告不算通过（页面顶部显示红）。不允许写成文字声明。

| # | 检查 | 怎么算 | 证据示例 |
|---|---|---|---|
| A | 溯源一致 | 所有套件记录的 commit 相同，`dirty` 为空；L4 常驻服务记录的 commit 等于该 commit。报告脚本运行前校验，不一致就拒跑 | 提交 `05a5a71`；服务 commit 同 |
| B | 跳过不算通过 | 实际执行数 = 用例总数；有跳过必须显式列出理由 | 30/30 执行 |
| C | 真实进程 | 每个被测服务在环境块里有 PID 与地址 | gateway pid 2548932 |
| D | 网络证据 | transport 层记录到的往返数 > 0；L4 的所有目标都是环境地址，出现 `127.0.0.1`/`localhost` 即 ✗ | `192.168.20.24:8070 × 41` |
| E | 独立核对 | 至少一个「核对：」步骤走被测系统之外的通道（直读对象存储或数据库、官方客户端查询），不以被测服务的回执为准 | 12 个核对步骤 |
| F | 替身声明 | 环境块声明的替身只有第三方；L4 替身为零 | L3：Trackman 拉取；L4：无 |
| G | 防假绿 | 见第 5 节：基线全绿，且每处改动都被守护用例抓住 | 7/7 被抓住 |
| H | 脱敏 | 扫描原始记录与页面：token、授权头（Bearer 后跟 token）、预签名签名、第三方分享链接；命中则拒绝生成 | 0 命中 |
| I | 可复现 | 原始记录与页面同存，页脚 sha256 与重新生成命令齐全 | 4 份记录 |

## 5. 防假绿改动（mutation）

Rule 10 要求每条新测试都证明自己会红；报告把它变成可重放的运行，而不是开发时的一次性手工操作：

1. 在被测提交上开一个**临时 worktree**，不在开发 worktree 里改代码。
2. 每个选中的用例集先跑一次**基线**（不改代码），必须全绿；否则改动后的红不能说明问题。
3. 每处改动只动一行真实风险分支（跳过删字节、不检查范围、游标多取一格、失败不隔离），跑守护它的用例，结果必须是红。
4. 每次跑完用 `git checkout -- <file>` 还原并校验文件已复原；最后记录 worktree 是否干净并删除它。
5. 报告列每处改动：编号、改坏了什么、守护用例、改动后结果、结论（抓住 / 漏过）、diff。漏过即检查 G 为 ✗。

## 6. L4 数据卫生

- L4 用例用 teardown 夹具登记自己写入的数据，**成败都删**；中途失败留下的数据不能留在共享环境里。
- 真实第三方数据（真实报告、真实账号数据）在用例结束时删除，编排器的暂存目录一并清空；报告写明「真实数据已删除」。
- 第三方凭据类输入（分享链接、token）只从环境变量或 0600 文件读，不进命令行参数、日志、记录和页面；检查 H 覆盖原始记录。
- L4 用例检查被测服务日志与编排器本地存储里没有这些凭据。

## 7. 反模式

- 手写「测试环境」段落，或从上一次报告复制过来。
- 报告写「已验证写入成功」，但只断言了被测服务返回 200，没有独立核对步骤。
- L4 用测试夹具临时起服务冒充环境，或者在回环地址上跑「L4」。
- 用 skip 掩盖环境缺失，页面仍显示全绿。
- 改坏代码的验证只在开发时做过一次、没有记录，或在开发 worktree 里改完忘了还原。
- 报告页引用外部字体或脚本，脱离仓库打不开或样式错乱。
