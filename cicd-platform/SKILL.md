# cicd-platform

## Description

通过浏览器操作 `https://cicd.addx.live` 的上线单系统。平台是 Vue + Ant Design SPA，使用 hash 路由；登录入口是 `GitLab 登录`。

本 Skill 只操作上线单平台。部署清单和 CI 接入使用 `cicd-developer`，ArgoCD 日常 sync/rollback 使用 `argocd`，Jenkins 深度排障使用 `jenkins`。

按需读取：

- 创建、推进、部署、灰度或 Apollo 操作：先读 [references/sop.md](references/sop.md)。
- 需要核对网络请求或 UI 无法读取数据：再读 [references/api-reference.md](references/api-reference.md)。

## Rules

### 浏览器前置

优先使用可见浏览器工具；CLI 环境使用 `agent-browser`：

```bash
agent-browser --session <task-session> --headed open 'https://cicd.addx.live/#/task/list'
agent-browser --session <task-session> wait --load networkidle
agent-browser --session <task-session> snapshot -i -c
```

1. 每个任务使用独立 session；同一任务始终复用该 session。
2. 优先按可访问名称和最新 snapshot 的 `@ref` 操作，不缓存旧 ref，不猜 DOM。
3. 未登录时点击 `GitLab 登录`，让用户完成 GitLab SSO/MFA；不读取、记录或回显密码、cookie、token、localStorage。
4. OAuth 会经过 `gitlab.addx.ai`；限制域名时同时允许 `cicd.addx.live` 与 `gitlab.addx.ai`。
5. 登录成功后 URL 应回到 `/#/task/list`；否则停止并报告当前 URL 与可见错误。

### 标准执行闭环

每次操作严格执行：

1. **解析目标**：确定上线单 ID、项目、环境、动作，以及用户要求的 branch/commit、灰度比例或 Apollo 范围。
2. **读取最新状态**：直达 `/#/task/<id>/detail`，重新 snapshot；核对 ID、是否 `[废]`、是否已挂起、当前步骤、SQL/Apollo 标记、项目、branch/commit 和各环境部署状态。
3. **检查门禁**：目标按钮必须可见且 enabled。按钮禁用、角色不符或状态不符时停止；不得用 API 绕过 UI 门禁。
4. **展示动作摘要**：写操作前给出 `上线单 / 项目 / 环境 / commit / 当前状态 → 目标动作`。若发现与用户描述不一致，停止确认。
5. **执行一次**：重新 snapshot 后定位目标控件；避免双击或重试 POST。弹窗出现后再次核对内容再提交。
6. **验证结果**：等待页面或状态刷新，重新 snapshot；部署中每 10 秒查看状态，必要时打开日志。以页面最终状态为准，不以“点击成功”代替结果。
7. **交付证据**：报告上线单 URL、动作、前后状态、项目/环境/commit、操作者可见结果；失败时附页面错误或日志摘要。

### 写操作授权

用户消息已明确给出目标和动作时，可直接执行创建/编辑上线单、添加项目等准备动作。下列动作必须在最终点击前获得新鲜确认；若用户同一条消息已明确包含上线单 ID、项目、环境和该动作，可视为有效确认：

- PRE/GRAY/PROD 部署，取消正在运行的部署，回滚到上一成功版本。
- 灰度开关、比例、白名单/黑名单、预扩容、流量切换、缩容。
- Apollo Pre/Prod 发布，以及上传验证结果。
- 完成测试、自动化校验、审批、灰度验证、验收等状态推进。
- 特批、作废、挂起、恢复、跳步、工作流回退。

确认摘要必须显示实际影响，尤其是 PROD、流量比例和回滚目标。一个确认只授权一个具体动作；目标、commit、环境或比例变化后重新确认。

### 上线单状态机

正常状态为：`新建(1) → 测试(2) → 校验(3) → 审批(4) → 灰度(5) → 完成(6)`。

- 只点击当前步骤允许的按钮；不要通过管理员跳步替代真实部署或验证。
- 快捷上线单、Apollo 上线单和特批上线单是不同模式，不能互相推断门禁。
- `[废]` 或已挂起上线单默认只读；恢复或特批必须按高风险动作处理。
- 角色和动作矩阵见 SOP；看不到按钮通常表示角色或状态不满足，不要自行升级权限。

### 部署与回滚

1. PRE 首次部署可能要求选择 Git 分支。选择后核对 UI 展示的 commit；GRAY/PROD 应沿用已记录 commit，不临时换分支。
2. 点击部署前记录当前成功版本与目标 commit；PROD 必须明确三者：地区、项目、commit。
3. 部署状态：成功、失败、进行中、中止。进行中不要重复点击；优先等待或查看日志。
4. 取消按钮只在平台允许时出现；某些项目不可取消，不得绕过。
5. `回滚` 会部署上一次成功版本。先读取当前版本和回滚目标；回滚成功后重新验证环境状态。

### 灰度安全规则

1. CN 当前无 APISIX 灰度，页面提示无需预扩容时不要强行操作。
2. 把“灰度关闭 → 开启且实际 gray 比例大于 0”或“目标实际 gray 比例大于当前线上有效比例”定义为**扩量**。US/EU 扩量必须先完成 `灰度放量` 预扩容，等状态成功且预扩容目标覆盖当前目标后，再点 `确定(放量切流量)`；预扩容进行中、失败或目标不足时禁止切流。
3. PROD 页面输入的是 PROD 比例，实际 `gray.ratio = 100 - PROD 输入值`。确认时同时显示输入值和换算后的实际 gray 比例。
4. 纯白名单/黑名单调整、实际比例不变或降低时不触发预扩容；若同一次操作还提高实际比例，仍按扩量执行预扩容。
5. 调整名单时先读取完整现值；“添加”必须合并去重，“移除”只删除精确项，“替换”必须由用户明确授权。提交前展示前后差异，禁止无意覆盖整份名单。
6. 缩容前必须先关闭灰度并保存，重新读取确认 `enabled=false` 且 gray 流量已收回，再缩容；不得把缩容当作收流量。
7. 标记为灰度只读或与 `iot-service` 共享配置的项目只查看，不写入。

灰度动作矩阵：

| 动作 | 预扩容要求 | 完成信号 |
|---|---|---|
| 开启灰度且目标实际比例 > 0 | US/EU 必须先成功 | 保存后重新读取 enabled=true、实际比例正确 |
| 提高实际 gray 比例 | US/EU 必须先成功 | 预扩容 target ≥ 目标，再切流并回读 |
| 降低/保持实际比例 | 不需要 | 保存后回读比例 |
| 只调整白名单/黑名单 | 不需要；同时提高比例则需要 | 回读完整名单与预期一致 |
| 关闭灰度 | 不需要 | enabled=false、gray 流量为 0 |
| 缩容 | 必须先完成关闭灰度 | Jenkins 缩容已触发/完成 |

### Apollo 与管理员动作

1. Apollo Pre/Prod 发布前先 Review；若页面提示 `ApolloReview后有新的变更`，停止发布并重新 Review。
2. Apollo Prod 仅在 Pre 发布成功且上线单位于校验步骤时执行。
3. 工作流回退只重置平台步骤与下游门禁，**不会撤销已发生的部署或 Apollo 发布**；必须在确认摘要中明示。
4. 跳步仅用于新建/测试/校验门禁；灰度与验收需要真实部署，不能跳过。
5. 挂起会冻结推进、部署、灰度和审批；恢复后先重新读取所有状态再继续。

### API 与页面边界

- 浏览器 UI 是写操作的首选和事实源。API 默认只用于只读诊断；未经明确授权不直接调用 POST。
- 不用 API 绕过 disabled 按钮、角色、状态机、确认弹窗或审计原因。
- 当前 `/project` 下的创建、成员、审核、删除、配置和 Pipeline 页面存在模板/空操作；不要宣称已支持这些写操作。上线单内的 `添加项目` 是已验证入口。
- 页面失败但下游 Jenkins/ArgoCD 可能已触发时，先查状态和日志，禁止盲目重试。

## Examples

### Bad

```text
用户：帮我看看上线单 351。
AI：看到 PROD 按钮了，顺手点了部署，并在进行中时又点了一次。
```

```text
用户：把美国 PROD 调到 80%。
AI：直接把 gray.ratio 写成 80%，没有说明 PROD 输入 80% 实际等于 gray 20%。
```

### Good

```text
用户：部署上线单 351 的 iot-service 到美国 PROD，commit abc1234。
AI：打开 /#/task/351/detail，确认上线单未作废/未挂起、项目为 iot-service、美国 PROD 按钮可用且目标 commit 为 abc1234；展示最终摘要后只点击一次部署，轮询至成功，并返回上线单链接与最终版本。
```

```text
用户：把上线单 420 的美国 PROD 调到 80%，并完成放量。
AI：先读取线上灰度配置，明确“PROD 输入 80% → 实际 gray.ratio 20%”；若 20% 高于当前实际 gray 比例，先预扩容并等待成功，再经确认切流量，最后重新读取配置验证。
```
