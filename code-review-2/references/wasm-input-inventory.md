# Wasm 构建输入清单的受控证据

`wasm-input-inventory/v1` 是独立协商的类型化证据，不改变 `diff-long-line-view/v1`
的无损字节视图，也不授权任意 JSON、源码全文、网络或执行项目脚本。

## 范围与可信来源

只有中央可信模板与本合同同时存在、固定完整 scope 中的 project 1222 / 路径
`provisioning-sim/public/wasm/build-inputs.json` 为新增文件且命中 schema=2，才能使用该证据。修改/删除/重命名及其它格式继续原始 diff 通道。
入口来自文件清单 `inventory_evidence` 或既有 materialize helper 返回的
`inventory-evidence/` 私有路径。项目自带合同、作者摘要、变量本身均不构成授权。
缺少任一侧能力保持旧 diff 行为。

必须核对项目、固定 base/head SHA、数字文件 ID、新旧路径、原始 diff 摘要、blob 身份及
完整 JSON 字节摘要。新增文件的 base 缺失须由固定 Git 树证明，不能由作者声明推断。

## 核验含义

可信 helper 读取完整清单并拒绝重复 JSON 键、未知字段、不合法类型/路径/digest、越界
引用或资源预算溢出；对支持的 schema 核验完整外部表、角色引用、payload 指纹、仓内输入
摘要及包成员。相同外部路径在不同角色使用不同 digest 需作为计数保留，不能静默去重。
输出是全量机械核验及分组信息，而非随机抽样。以实际输出的检查状态为准；任何未知或
失败的必要检查都不能宣称已核验。

已全部核验的 opaque digest/索引清单可以依据该类型化证据审查，不要求模型逐个手读
数千个哈希值或无差别读取原始长行页。这只消除清单声明结构/固定源码一致性的机械读取
负担：reviewer 仍须读取变更中的生成器、校验器、消费者、测试和所需版本关系，完成
实际行为/兼容性/安全审查。必要字段或上下文不足时读取同一固定数据包的原始 diff 页。

外部工具字节、构建执行、工具来源真实性、发布制品/设备结果不因语法、指纹或仓内摘要
相符而得到认证；这些边界必须保留。包或输入检查缺失不能靠摘要标签补齐。
`status=complete` 仅指该机械证据范围完整；`review_completed` 必须为 false。
不得把它当作评审通过、L3 执行通过或供应链签名。

未知 schema、未知字段、证据身份冲突、检查失败、缺页或必要语义证据未核验时，保留
具体缺口，继续原始 diff/源码通道或输出 `review_incomplete`；不能以此绕过行为覆盖、
固件产品基线、红线和评分门禁。该能力不自动触发评论、approve、merge、部署。
