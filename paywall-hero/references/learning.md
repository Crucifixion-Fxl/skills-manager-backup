# 经验管理

生成任务的需求、候选版本、选图决策和 CMS 操作结果以对应 GitLab Issue 评论为记录入口；正式图片存入 Marketing CMS Media，不要求提交到产品代码仓库。`feedback/` 只保存用户明确要求转化为 Skill 长期规则的反馈；这里是 Skill 项目资料，不是 Codex 全局记忆。

每条记录包含：日期、产品、关联案例、用户原话、适用范围（本次/产品/通用）、规则类型（硬性约束/偏好）、候选规则、状态、验证证据。

用户未指定长期范围时按本次修改处理。用户明确要求“以后默认”时可以更新该产品偏好；记录来源及验证状态，不能声称已通过历史回归。通用化前检查是否只是当前构图特例。

正式产品规则放各产品 `rules.md`。精选、脱敏且值得教学的案例才放 `examples/`；普通商业实验通过 Issue 和 CMS 追溯。失败案例说明具体缺陷，不把整张图判为所有方面都不可用。

后续远端采用反馈→候选规则→案例验证→合并的流程。安装目录不是 Git checkout 时不要推送它；远端变更遵循当次用户授权，在公司仓库的独立分支提交。规则冲突优先核对本次明确要求及适用范围，不能通过累加矛盾规则解决。
