# Asset Key Definition

本文件统一定义 Dagster Python 资产 `key` 的结构、命名和权限约束。

## 1) 结构定义

- `key` 必须是二段结构：`[<business_domain>, <asset_identifier>]`
- `key[0] = business_domain（业务域）`：表达资产归属域
  - 对数据资产：通常使用落地库名，并且只能取本文档白名单值
- `key[1] = asset_identifier（资产标识）`：表达资产内容或功能，使用小写英文和下划线
  - 对数据资产：通常使用落地表名，并遵循本文件命名规则

## 2) key 生成规则

- 先判定资产类型：
  - 数据资产：脚本意图是产出并交由 Dagster 入仓的数据
  - 非数据资产：仅借助 Dagster 进行调度任务，不产出入仓数据
  - 若无法直接判断，必须先询问调用者：
    1) 脚本是否会产生数据？
    2) 产生的数据是否需要写入数仓？
  - “会产生数据且需要写入数仓” => 数据资产
  - “仅调度功能，不在 Dagster 产生任何数据” => 非数据资产
- 先生成候选 `key=[key[0], key[1]]`，再做业务域与资产标识的约束校验
- 生成顺序建议：
  - 先确定 `key[0]`（业务域）
  - 再确定 `key[1]`（资产标识）
  - 最终形成完整 `key`
- 当信息不足时：
  - 先根据数据来源/业务语义推断候选值
  - 必须让用户确认后再落地
- 当无法可靠推断时：必须先询问用户，不允许默认拍板

## 3) 业务域选择规则（key[0]）

- `key[0]` 表达资产归属域
- 数据资产场景下，`key[0]` 通常使用落地库名
- 数据资产场景下，`key[0]` 只能从以下白名单中选择
- 非数据资产场景下，`key[0]` 使用任务所属业务域，建议优先使用以下白名单值保持一致

| 可选业务域（通常对应库名） | 描述 |
|----------|------|
| `a4xmanage` | 后台数据管理 |
| `abtest` | AB业务 |
| `analytics` | 埋点业务 |
| `b2b` | B2B业务 |
| `bind` | 绑定业务 |
| `common` | 公共数据 |
| `device` | 设备业务 |
| `user` | 用户业务 |
| `factory` | 工厂业务 |
| `amazon` | 亚马逊电商爬虫数据（权限管控，仅运营角色可访问） |
| `ecommerce` | 电商业务数据（权限管控，仅运营角色可访问） |
| `fproject` | F项目业务（权限管控，仅运营角色可访问） |
| `bproject` | B项目业务（权限管控，仅运营角色可访问） |
| `cproject` | C项目业务（权限管控，仅运营角色可访问） |
| `finance` | 财务业务（权限管控，仅财务角色可访问） |
| `vip` | 增值业务（权限管控，仅增值业务角色可访问） |

## 4) 资产标识命名规则（key[1]）

- `key[1]` 表达资产内容或功能，使用小写英文和下划线
- 数据资产命名规则：
  - `key[1]` 通常与目标表名一致
  - 建议统一使用格式：`ods_<source_or_function>_<suffix>`
  - `source_or_function`：使用数据来源或业务功能命名，例如 `aws_bill`、`shop_order`、`device_event`
  - `suffix` 与调度/同步类型映射：
    - 天全量：`df`
    - 天增量：`di`
    - 小时全量：`hf`
    - 小时增量：`hi`
  - 示例：
    - AWS 账单按天增量同步：`ods_aws_bill_di`
    - 店铺订单按天全量同步：`ods_shop_order_df`
    - 设备事件按小时增量同步：`ods_device_event_hi`
- 非数据资产命名规则（仅调度任务）：
  - `key[1]` 直接使用功能名（`<function_name>`）
  - 使用小写英文和下划线（如 `clear_db_cache`、`sync_config`）
  - 不使用 `ods_` 前缀，也不使用 `df/di/hf/hi` 后缀
  - 推荐展示形态：`<business_domain>.<function_name>`
  - 示例：`AssetKey(["a4xmanage", "clear_db_cache"])`（展示为 `a4xmanage.clear_db_cache`）

## 5) 权限提示规则

- 若描述包含“权限管控”字样，使用该业务域前需提示用户角色限制
- 若用户角色与描述不匹配，应中止并要求用户确认访问权限
