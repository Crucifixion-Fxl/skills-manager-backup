# 执行效率与证据复用

适用于已授权的实现、恢复任务和代理调度。节省模型往返与上下文读取，同时保留项目要求的审批、测试、黑盒验收、独立评审和安全门禁。执行授权不扩展外部写权限，也不自动授权委派。

## 按可验收功能调度

- 一个任务包含文件 owner、范围、依赖、通过条件和回执路径。简单改动直接实施；独立模块在宿主允许且已授权委派时派发，提醒 worker 保留他人改动。
- 一次派发足够完成一个可验收功能的上下文。非紧急追加指令合并；完成、阻塞或关键发现再通知。影响正确性、安全或正在执行的错误操作时立即纠正。
- 调度按各任务自身依赖与 Gate；慢 build、CI 或人员回复只阻塞依赖它的任务。汇报以可验收功能为单位，不固定每三任务停顿、不逐个小步骤请求批准。

## 缩短模型往返与输入

- 将复制、打包、hash、回执生成/校验及日志摘要放入可重复执行的脚本。可并行的独立读取或检查在一次工具调用中批量完成，依赖操作、修改与审批保持顺序。
- 先读 SSOT 与相关 diff，只取必要代码、失败摘要和证据定位；完整日志留在 artifact，遇到未知失败再读对应片段。不要为生成摘要另建一套手工真相。
- 子任务使用精简 handoff 与必要文件，避免默认继承全部历史。长主会话在功能边界形成可靠 handoff 后接续：保留授权与约束、未完成任务、owner、候选版本、有效证据、下一步与恢复条件；不为省上下文中断正在运行的任务。
- 模型按难度与宿主能力选择，在授权范围内让低成本模型处理机械任务；集成判断、复杂故障和独立评审保留合适模型。不要未经授权切换指定模型或外部服务。

## 环境与验证

- 新 worktree 先准备依赖、生成/build 产物、测试服务、磁盘、端口与数据隔离；环境失败单列，不能当作行为 RED。环境未变不重复 setup。
- 修改期间跑受影响测试；集成 owner 在干净候选版本跑必要完整 CI 与黑盒验收。维护一个明确的候选版本与证据入口。
- 复用条件是版本、依赖、配置、产物和数据环境相同，且成功回执含命令/target、日志或 artifact、最终退出码。merge/rebase、相关变更、失败或未知结果使对应证据失效，重跑受影响范围；新候选需重新满足其集成 Gate。测试 accepted、启动或排队不等于测试通过。
- 长测试只启动一次，保存 handle/PID、日志、超时和最终退出码，优先完成通知；无通知时有限退避检查，不高频轮询或长循环 sleep/tail。无持久机制不承诺 session 关闭后仍会监控。
- evidence、receipt 和摘要由脚本从真实运行生成。保留必要的内容 hash 与审批证据；不要为每次读取或微小汇报生成重复候选副本和独立回执。

## 评估优化效果

比较相同验收范围的完成结果、总耗时、模型调用、非缓存/缓存输入、输出、失败重跑及机械操作次数。减少调用不能以降低验收质量为代价。

累计 token 按线程取时间窗增量，排除继承基数和重复快照；子代理按父子关系归组，保留模型与速度档位。reasoning 通常已包含在 output，按日志实际 schema 确认后计算。token 与账号 quota 分开报告，不把 token 占比直接换成额度占比，也不将其他设备或缺失记录的消耗归到本机。
