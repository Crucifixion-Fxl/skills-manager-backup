# 已批准计划的实施与验证调度

适用于 dev-workflow 的连续实施模式。先核对授权和有效 Gate；本参考不授予平台写入、发布或人员联系权限。

## 可验收功能与依赖

按功能或模块组织 wave，每项只记录目标、文件 owner、Depends on、适用 Gate 和验收命令。已有计划满足这些信息就直接复用，不再创建第二份计划。

- 执行依赖已满足的任务；展示批次不设全局 barrier。例如 T1 已完成、T2 前端还在 build，T3 仅依赖 T1，则 T3 可继续；需要 T2 的集成任务仍等待。
- 简单改动直接实施；独立模块可在委派授权和宿主能力范围内并行，避免多个 agent 修改同一文件或共享环境。并发数按文件冲突和机器资源选择，不追求 agent 数量。
- 只读/仅规划请求止于草稿。计划的批准不代替缺失的 PO exact-hash、方案、QA、发布等 Gate，也不解锁宿主 Plan Mode。
- 已批准范围发生实质变化时记录差异并获取适用批准；未变化的部分继续，不重新讨论全部设计。

## 实施前准备环境

首次进入隔离 worktree 或环境发生变化时，只检查当前任务涉及的前置条件：

1. 固定候选源码与子模块版本，确认目录/分支所有权；复用项目 setup target 和锁定依赖。
2. 检查相关 build 产物（例如 web/dist、生成协议、SDK wheel）与源码一致；缺失/过期先重建，不把环境失败当作产品失败测试。
3. 确认测试服务健康、磁盘容量、可写目录、端口、数据卷与 seed/migration，隔离自己的环境，不清理其他 session 的数据或服务。
4. 提前确认必需的 registry/测试凭据访问，只验证可用性，不复制凭据。缺权限则记录 owner 和恢复条件，继续不依赖它的工作。

环境未变化时不重复安装、build 或巡检整套依赖。环境检查不替代验收测试。

## 验证分层与证据复用

- 开发内环：行为变更先确认相关测试因该行为失败，修改后运行受影响单测/契约测试；再覆盖关联集成路径。
- 集成候选：唯一集成 owner 在干净候选版本上运行当前 CI 的必要完整作业（包含相关 opt-in/main-only 门禁）及 AC 对应的跨服务/黑盒验收。不能用 package 单测代替真实装配或跨服务验证。
- 记录一次真实运行的源码 commit/dirty 状态、子模块与构建制品版本、依赖/配置、环境与测试数据边界、命令、退出码、用例结果和报告位置。同一候选版本与环境完全未变、结果完整成功时，多个流程步骤可引用同一回执，不机械重跑。
- 新 diff、merge/rebase、依赖/配置/产物/数据变化、失败、partial、skip、不明退出码或 flaky 结果都会使相关证据失效，重跑受影响范围与必需完整门禁。未运行记 pending，不能把旧 SHA 的结果改标成新 SHA 验收。
- 自审以可验收 wave 的 diff 为单位；新的 diff/契约变化或 reviewer 修复需要复审。保留项目要求的独立 reviewer、敏感域专项审查和 exact-hash Gate，不用自审/缓存结论绕过。

## 长任务与外部等待

长测试/CI 只启动一次，记录 task handle 或 PID、日志路径、超时与最终退出码。工具有完成通知时优先使用；没有通知时有限退避检查同一任务，不重复启动测试、不在一个 Bash 调用里长循环 sleep/tail。后台启动、HTTP 200 或进程退出都不等于测试成功，必须取回完整结果。

等待只阻塞依赖该结果的任务。仍有独立工作时继续；确实没有可做任务时保存进度、阻塞 owner、恢复条件与跟进方式，如实交付 blocked/pending。没有持久后台机制时，不承诺结束 session 后会自动监控或恢复，也不为此另起未经授权的常驻消费者。

对人员请求和 CI 状态只在有状态变化、关键失败、确需决定或到达约定跟进时间时通知。发出请求不是批准，提醒不是批准，验收未完成不能关闭 issue。

## 恢复与交接

一个功能一个集成 owner；wave 完成、阻塞或实质状态变化时更新现有 progress。handoff 只保留目标、已确认决策、版本/分支、验证结果、未满足 Gate 和下一项可执行任务，并链接 SSOT。压缩/恢复先核实这些状态，不重读无关历史、不重复派发已完成任务。
