# 决策支持报告：中立性与证据分层

本文件只在输出 `decision_support_report` 或 `recommendation_memo` 时读取。目标是让报告更容易用于决策，同时避免分析者通过标题、筛选、阈值或建议替负责人或请求者选择答案。

## 1. 决策导向不等于给答案

决策支持报告按“待决定什么”组织证据，而不是按问卷题序堆表。它可以说明现有证据能排除什么、缩小什么范围，各方案分别有哪些支持证据、反证和未知，以及区分方案还需要什么信息。

除非用户明确要求 `recommendation_memo`，不得写“应该选 A”“优先做 B”或用更委婉的措辞实现相同引导。后续研究方法应列为与缺口对应的可选证据路径，不默认其中一种就是下一步。

## 2. 主报告与证据层

主报告可以压缩，但不得变成不可审计的摘要。默认采用两层结构。

主报告包含：

- 少量、按研究问题重要性排序的中性事实结论；数量由范围和证据决定；
- 原始研究目标覆盖表；
- 按待决问题组织的关键证据；
- 每项证据的测量限制和未回答问题；
- 需要负责人决定的事项，但不替负责人选择。

证据附录包含：

- 受访者实际看到的原始题干与选项；
- 每题完整人数、分母和分布，包括中间档与不利于主叙事的结果；
- 所有派生指标的定义；
- 统计方法、多重比较、敏感性分析、剔除规则和数据质量；
- 去标识化用户原话明细与主题编码方法；
- 主报告每个关键数字到原题或结构化数据的可追溯关系。

主报告必须列出每个原始研究目标的状态：`主文回答 / 证据附录回答 / 数据不足 / 未测量`。不能仅因某题不支持主叙事就省略。

主报告按待决问题而不是问卷顺序组织。一道题可以支持多个待决问题；同一待决问题也可以综合多道题。完整逐题记录属于证据层，不要求在主文重复。

### 2.1 严谨性信息的三级放置

1. **紧邻发现**：如果限制会改变结论含义、可能推翻结论，或阻止读者把态度误当行为、关联误当因果，必须紧邻相关发现。正文用一到两句说清，不得隐藏。
2. **轻量证据边界**：如果限制只约束外推范围、测量口径或下一步用途，用统一的“证据边界”信息框、侧栏或较小正文呈现，避免打断主叙事。
3. **方法与审计附录**：抽样细节、完整题目分布、统计公式、多重比较、交叉分析降级记录和重复性说明放到证据层。

同一限制只在首次实质相关的位置完整说明。后文需要时短链回证据层，不重复粘贴。

### 2.2 视觉层级与可访问性

- HTML、PDF、文档或网页支持样式时，主结论使用正文主字号；“证据边界”可使用略小字号、较低强调度和左侧边线，但仍需满足正常阅读的字号与对比度，不得靠悬停才能看到。
- 不建议只靠更换字体传达证据等级；同时使用明确标签和版面位置，确保复制为纯文本后仍能理解。
- Markdown 默认使用：`> **证据边界：** ...`。不要用连续多层引用、警告图标或大段斜体制造视觉噪音。
- 会推翻结论的限制不能用小字或低对比度处理，应直接写进主段落。
- 证据附录必须可从主文直接到达；不得以“完整版另存”但不提供路径的方式省略证据。

### 2.3 研究目标的最低可见度

通用定义以 `structure-and-scope.md` 的“范围覆盖表”和“主报告与证据层”为准。决策支持报告额外使用“一目标一行”的答案索引，让每个目标可扫描、可定位、可单独引用。核心摘要只保留最重要的少量发现；结论晋级门槛只管理派生分析，不管理原始目标是否可见。没有负责人确认时，不自行把目标降到附录。

## 3. 标题与结论中立性

标题必须直接描述测量结果，不写策略口号、因果解释或未测量的先后关系。

- ✅ “方案 A 是本题中最常被选择的信任信号”
- ❌ “先证明，再宣传”
- ✅ “测试价格 X 的正面价值评价为 51%”
- ❌ “价格 X 是最佳价格”

核心结论只放数据直接支持的内容。分析者合成的用户路径、机制或产品叙事移入“待验证解释”，并至少列出一个合理替代解释。

直接回答必须保持构念一致：题目测量“关注渠道”时，不把结果直接写成“可招募渠道”或“投放效果”；样本中某特征常见时，不把它命名为市场结构。相邻的业务用途可以放在“对待决问题的影响”，但要明确它是应用或待验证解释，不是题目直接测得的事实。

## 4. 阈值、合并口径和证据等级

- 不得把事后选择的 50%、前 3 名、平均分 4 分等阈值写成自然存在的决策边界。
- 预先由负责人或研究计划定义的阈值可以用于判断，但必须写明来源。
- 分析者为便于阅读创建的合并指标必须给公式，并链接完整分布。
- 如果合理的另一种合并方式会改变结论，主文必须并列展示或声明敏感性。
- 不使用没有规则的“高/中/低置信度”。如需证据等级，预先定义至少包括：样本与目标人群匹配度、题目对构念的直接程度、是否存在真实取舍或行为，以及结论对分析口径的稳定性。否则直接描述限制。

## 5. 对称呈现与选择架构

当报告讨论多个方案时，对每个仍可行方案使用同一结构：

| 方案 | 支持证据 | 不支持或相反证据 | 未知 | 需要的决策输入 |
|---|---|---|---|---|

视业务问题纳入“维持现状”“暂不决定”或“不推出”。不要只为分析者偏好的方案写具体行动，而把其他方案写成抽象标签。

分组差异必须同时给各组分母，不从观察性差异推断原因。多选比例不能直接当优先级；量表均值不能在存在天花板效应时包装成路线图排名。

## 6. 中立但不枯燥

中立要求不替读者选择，不要求把主文写成逐题清单或免责声明集合。行动感来自决策张力和信息增量，而不是分析者口号。

每个核心章节优先使用四段节奏：

1. **直接回答**：一句可由数据支持的答案；
2. **关键差异或张力**：用最能改变理解的具体对比，不只报最高比例；
3. **对待决问题的影响**：说明证据缩小、排除或暂时无法区分什么，不指定方案；
4. **尚缺证据**：只列会改变当前判断的缺口，方法细节移到后部。

主文不必为每个待决问题展示完整题表。优先使用一个关键数字、一个有意义的对比或一张精简表建立张力，再把完整分布链接到证据层。

允许使用清晰、有力度的表达，但标题必须是事实。优先写具体变化、不同口径的边界或分布对排序的影响，不要写“用户很兴奋”“机会巨大”“必须立刻行动”。

不要在每个数字后重复同一限制。样本代表性等全局限制集中说明一次；题目特有的限制紧邻该发现；完整方法放证据附录。只有限制会实质改变当前结论时才在核心段重复。

“对称呈现”不等于每节机械套五列表格。只有存在多个真实可选方案时才用方案表；单一发现可用短段落、对比表或小型图。主文保留阅读节奏，证据层保留完整性。

## 7. 决策相关交叉分析

边际比例只能说明每个答案分别出现多少，不能证明答案由同一批人选择。写核心结论前逐项检查：

- 是否声称两个需求共同出现？
- 是否把多个选项串成同一用户路径或机制？
- 是否声称某类用户更重视、接受或使用某项内容？
- 是否依据两个回答组合定义细分人群或方案？

任一为“是”，必须读取 `statistical-defaults.md` 的交叉分析规则，并使用受访者级数据验证。数据不可用时，删除联合叙事或明确标为未验证假设。

只做会改变解释或决策的交叉，不枚举所有题目组合。报告先写明分析问题和用途，再给交叉结果；探索性发现必须标记，不能包装成预先假设。

### 7.1 先分析，再决定是否展示

完成交叉分析后逐项通过以下晋级门槛。分析结果不会因为“已经计算”“达到统计显著”或“比边际分布更复杂”而自动进入报告。

1. **明确用途**：它回答了哪个研究问题、推翻了哪个合理假设，或会改变哪个待决事项？
2. **信息增量**：相比单题分布，它是否带来读者原先不知道、且并非选项定义即可推知的信息？
3. **非机械相关**：关系是否可能主要来自重复措辞、包含关系、同一矩阵、题目顺序提示、共同方法或常识性配对？若是，不能当作有启发的发现。
4. **实际意义**：差异或关联是否大到可能改变判断？仅有小 p 值、很小效应或大样本驱动的显著性不够。
5. **稳健性**：合理的分组、阈值、剔除或替代解释是否会改变结果？关键混淆无法处理时只能作线索。
6. **可辨别后果**：它是否导致不同的候选方案、分层、信息表达或验证设计？如果所有合理结果都导向同一下一步，则决策增量有限。

### 7.2 分层去向

- **进入核心结论**：用途明确，带来实质信息增量，非机械相关，效应具有实际意义，且会改变决策范围或方案。核心结论仍按研究问题的重要性排序。
- **进入主文章节的辅助证据**：能校验或限定一个核心结论，但本身不足以成为结论。正文最多用一小段说明它是否改变原判断。
- **进入补充证据或方法附录**：探索性、符合常识、效应较小、存在明显共同方法偏差，或只证明“这些答案有重叠”。明确写“未改变当前判断”。
- **不报告**：没有明确用途、重复既有信息、不可解释，或属于大量事后组合中的偶然结果。可保留在内部分析记录以供审计。

反证和“没有差异”若能排除一个真实候选方案，也可能进入主文；不要只奖励显著结果。相反，语义完全对应的“问题 × 解决方案评分”、高基率多选项之间的重叠，以及符合选项定义的场景 × 配件，通常不能单独晋级。

## 8. 用户原话与开放题

- 核心结论优先使用主题分布，不用单条强烈原话做标题。
- 原话用于说明主题含义，不提高主题权重。
- 选取原话时覆盖主题中的常见表达和重要差异；按 `quote-and-openended.md` 在受控证据中保留必要的可追溯索引。
- 单人编码、编码规则变化或无法计算编码者一致性时明确披露。

## 9. 建议备忘录的额外要求

只有用户明确要求推荐时才进入 `recommendation_memo`。推荐前先列业务目标、候选方案、约束与不可逆成本、负责人提供或确认的决策标准，以及研究证据之外需要纳入的信息。

如果关键标准缺失，只能交付“方案与权衡”，不能伪造一个最优答案。推荐必须与 findings 分开标记，说明哪些部分来自数据、哪些来自业务判断。

## 10. 交付前中立性检查

- [ ] 每个核心标题都能由紧邻的数据直接支持？
- [ ] 是否把多选最高项误写成先后顺序、唯一优先级或因果驱动因素？
- [ ] 是否发明了负责人未确认的价格、分数或排名阈值？
- [ ] 合并指标是否给出定义，并保留完整分布链接？
- [ ] 是否记录了所有原始研究目标的去向？
- [ ] 是否省略了反例、中间档、无变化或不利于主叙事的数据？
- [ ] 是否把分析者合成的故事明确标为待验证解释，并给出替代解释？
- [ ] 是否使用了没有规则的置信等级？
- [ ] 后续证据路径是否与缺口对应，而不是伪装成唯一建议？
- [ ] 没有明确要求推荐时，报告是否仍把最终选择留给负责人？
- [ ] 核心叙事是否暗含答案共同出现、用户路径或分群差异？如有，是否提供了相应交叉分析？
- [ ] 每项交叉是否记录明确用途、信息增量、机械相关风险、实际意义、稳健性和可辨别后果？
- [ ] 是否把“分析已经完成”或“统计显著”误当成主文收录理由？低增量分析是否已降到补充证据或不报告？
- [ ] 核心结论顺序是否由研究问题的重要性决定，而不是由新增分析的复杂度或新颖度决定？
- [ ] 主文是否用关键差异和决策影响形成节奏，而不是靠口号，或反过来被重复限制拖成审计清单？
- [ ] 主文是否按待决问题组织，而非恢复为问卷顺序或逐题报告？完整题目是否仍在可达的证据层？
- [ ] 限制是否按影响程度进入正文、证据边界或方法附录？是否用小字隐藏了可能推翻结论的风险？
- [ ] 即使样式丢失，标签和纯文本是否仍能表达发现与限制的关系？
- [ ] 每个来自 brief、请求者要求或研究工具明确测量的目标，是否在主报告有可见答案或状态？是否误把“附录有数据”当成“主文已回答”？
- [ ] 是否未经负责人确认就把独立目标合并成“其他”、只留一行或降到附录？
- [ ] “没有明显胜出项”“数据不足”或“题目无效”是否也被当作需要呈现的研究答案？
