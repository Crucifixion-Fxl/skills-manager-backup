# Survey Fieldwork and Analysis

完整问卷在发布前使用本参考；局部改题不需要生成完整 fieldwork 文件。

## 1. Sampling plan

记录 target population、sampling frame、eligibility、exclusions、招募渠道、经验新鲜度、quota/segments 和预期有效率。

- 估计比例时，根据所需精度、置信区间和预期设计效应说明目标样本，而不是只写一个习惯性 N。
- 分群比较声明各组最低可解释样本；关键 routed subgroup 不足时定向招募、降级结论或换方法。
- Convenience sample、邮件用户、App 弹窗、社群和自愿报名的 coverage/self-selection 限制进入报告。
- 多 collector/wave 保留来源，不能在招募条件或 instrument 改变后无说明合并。

## 2. Pre-analysis plan

发布前为核心结果定义：

- numerator、denominator、unit of analysis 和 reference period；
- routing eligibility、partial response、missing、don't know 和异常值处理；
- 多选、ranking、scale 与开放题的具体汇总方式；
- primary 与 exploratory analyses；
- subgroup cuts、最低 n 和多重比较风险；
- weighting/calibration 是否需要及依据；
- telemetry linkage 的 key、许可、时间窗与 linkage bias；
- high/low/mixed result 对应的 decision rule。

看到结果后改变主要指标或排除规则必须标为 post hoc，不得静默改写。

## 3. Soft launch and quality

正式扩大投放前，按风险使用小规模 soft launch 检查：

- invitation 到开始、首题退出、页面/题目 breakoff；
- 典型与最长完成时间；
- routing、Other、多选、随机化和导出编码；
- 异常短时长、重复/机器人答卷、straightlining 和矛盾回答；
- 手机/桌面或渠道之间的明显差异。

预先定义 continue / pause / revise 条件。Attention checks 会增加负担并可能误伤认真用户，只在用途明确时使用；质量规则优先标记并做敏感性分析，不无依据静默删除。

## 4. Live versioning

开始收集后修改题干、选项、逻辑、刺激、required 或招募条件时：

1. 保存旧 instrument 与变更时间；
2. 判断 construct、estimand、可达样本或编码是否改变；
3. 使旧 renderer/response mapping 证据失效；
4. 需要时建立新版本或新 wave；
5. 在分析中分版本，并说明能否合并。

修正纯显示 typo 也要记录，但不必机械拆 wave；判断依据是回答含义和数据可比性。
