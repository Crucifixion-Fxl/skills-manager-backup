# Integration Patterns — 决策卡

## 什么时候用

- 对接第三方 API：支付（Stripe/Airwallex）、消息（飞书/Slack）、云服务
- 外部系统不可靠：第三方有 downtime、限流、响应慢
- 外部模型与内部模型不匹配：第三方返回的数据结构和你的领域模型差异大
- 多个外部系统提供同类能力：需要统一抽象（如多个支付渠道）

## 核心概念速查

| 概念 | 一句话解释 | 追问示例 |
|------|----------|---------|
| **Anti-Corruption Layer (ACL)** | 在外部系统和内部模型之间加翻译层，防止外部模型入侵 | "接入这个 API 后，我们的代码需要到处写它的数据格式吗？" |
| **Circuit Breaker** | 下游故障时快速失败，避免级联雪崩 | "这个外部服务挂了 5 分钟，我们的系统会怎样？" |
| **Retry + Backoff** | 瞬时故障自动重试，指数退避避免风暴 | "这个调用失败了，重试安全吗？会不会造成重复操作？" |
| **Idempotency Key** | 保证重复请求只产生一次效果 | "用户点了两次支付按钮，会扣两次钱吗？" |
| **Timeout + Fallback** | 外部调用超时后的降级策略 | "调用超时了，用户看到什么？有缓存可以用吗？" |
| **对账机制** | 定期比对两个系统的数据，发现不一致 | "如果回调丢了，怎么发现这笔交易状态不一致？" |

## 与本 skill 的关系

- Step 2 的"集成模式"追问直接关联此卡
- Step 4 中任何依赖外部服务的模块都需要评估这些模式
- 与六边形架构配合：ACL = Driven Adapter 的职责

## 什么时候不用

- 调用内部可控服务：内部服务的可靠性和模型一致性高，不需要重型隔离
- 原型阶段只接一个外部 API：直接调用更快，等需要第二个时再抽象
